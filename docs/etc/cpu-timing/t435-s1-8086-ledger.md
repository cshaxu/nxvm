# T435 S1 - 8086 Manual and Model Ledger

## Status and boundary

This is block 1 of T435 S1.  T435 S5 corrects discovered corpus omissions:
`XLAT` (opcode `D7`) and 8086-only `POP CS` (opcode `0F`) were decoded
successfully but absent from the original S1 and S2 inventories. A subsequent
S5 decoder/manual reconciliation also found that the original S1/S2 contract
wrongly imposed the later-80386 LOCK whitelist on 8086. The 1979 manual and
Intel ASM86 material state that the 8086 LOCK prefix may precede any
instruction. The former claim of complete prefix coverage is therefore
withdrawn until every such successful prefix form has a finite L3 key and
runtime proof. It does not make a runtime change.
`INT`, `IRET`, `INTO`, `HLT`, `WAIT`, `XLAT`, and `ESC` are included;
external `INTR`, `NMI`, HOLD, READY/wait state, bus arbitration, 8087 execution,
and prefetch occupancy are inputs/events rather than retiring 8086 instruction
forms, and are separately labelled below instead of being smuggled into an
instruction number.

The current scalar source ledger has only 34 ordinary 8086 entries and five
string entries.  Its remaining successful forms reach the explicit
`SOURCE_UNALLOCATED` one-tick path.  That is a present L1 implementation fact,
not a proposed L2 result.  This ledger assigns every such form a target before
the later implementation phase may remove that path.

## FLAGS image and restore contract (T499 S12)

`PUSHF` and an interrupt frame publish an architectural FLAGS *image*; `POPF`
and `IRET` load the live FLAGS fields. They are not the same operation. The
8086/8088 manual explicitly says that software must make no assumption about
undefined bits in a `PUSHF` image (the defined-bit mask is `0FD5h`). In
particular, bits 12--15 are not a documented `Fxxx` result. Core uses zero
only as its deterministic canonical value for undefined fields, not as a
manual readback claim; tests assert only defined fields.
Authority: I86-UM-1979, Flag-Images and PUSHF/POPF descriptions.

## Rule vocabulary

`EA` means exactly the Table 2-20 value: displacement 6; base/index 5;
base/index+displacement 9; BP+DI or BX+SI 7; BP+SI or BX+DI 8; the respective
two-index displacement forms 11 and 12.  A segment override adds 2.  For each
odd-addressed 16-bit operand transfer, add 4.  These are L3 formula terms.

`W` is the documented external READY wait-state count where the instruction
formula contains it; it is not guessed by the CPU program.  `n` is a documented
repeat or TEST-pin wait count.  Prefixes are legal only where the decoder's
existing semantics make them legal; invalid/unsupported encodings are faults,
not successful-retirement rows.

For a manual range, fixed midpoint uses `ceil((low + high)/2)`.  That is a
labelled L2 emergency fallback only.  It preserves a single deterministic
result if a selected dynamic model cannot be applied; it never claims that the
midpoint is an Intel L3 value.

## Selected dynamic L2 contract: L2-86BOX-8086-G3

**Decision: selected.**  86Box may be used as an external, version-pinned L2
reference for the four Group-3 arithmetic families, subject to this contract.
The project must implement an independently written model; it must not copy,
translate, link, or import 86Box source.

The model input is the successful instruction's mnemonic (`MUL`, `IMUL`,
`DIV`, or `IDIV`), width, pre-execution arithmetic operands, and memory-form
facts. It counts serial shift/add decisions for multiplication and restoring
division subtract decisions for division; signed forms first normalize their
operands and account for sign-control decisions. The count is normalized to
the applicable Intel range, so queue/BIU accounting never becomes an invented
instruction scalar. The final memory cost is the manual's corresponding
memory-form range plus documented EA, segment-override, and odd-word additions.
A zero divisor or quotient overflow does not produce a successful result from
this contract: it reaches the separate exception-delivery owner.

The model's acceptance test is black-box, not source similarity: for all
selected 8-bit input combinations and an exhaustive or owner-approved
equivalence partition of 16-bit inputs, compare the independently implemented
result with the pinned 86Box normalised no-external-wait result.  Every
successful result must also lie within its I86-UM-1979 Table 2-21 range,
including the manual memory additions.  A disagreement with the manual rejects
the reference result; a disagreement only with 86Box is retained as a named
L2 divergence with the manual-bounded project result. Until those tests pass,
the dynamic model remains nonconforming; there is no fixed-midpoint or
anonymous one-tick fallback.

## Coverage and review result

The table accounts for every base 8086 mnemonic, every Table 2-21 operand
form, every conditional outcome, every legal prefix/repetition mode, all memory
EA alternatives, and each odd-word condition.  There are no `principle-only`
or `no timing` *instruction* rows in this 8086 corpus.  Four dynamic arithmetic
families have only ranges, so `L2-86BOX-8086-G3` is selected for their dynamic
L2 validation. All other successful-retirement rows have an Intel exact value or
formula and are proposed L3.  There is therefore no proposed L1 instruction
row.

Before implementation, the next T435 phase must mechanically expand this
grouped ledger into the decoder's concrete opcode/form/context keys and prove a
one-to-one mapping.  That is implementation preparation, not a deferral of any
manual or model decision made here.  Owner review is now required before the
80186 block begins.
