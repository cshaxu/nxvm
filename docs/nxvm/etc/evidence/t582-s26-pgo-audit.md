# T582 S26 — single-executor profile-guided compilation audit

A temporary x64 GCC profile-guided optimization experiment compiled the existing five CPU/timing/Machine memory translation units with training instrumentation, ran the existing fixed-work private-media guest, and recompiled those units using the generated profiles. It did not alter project CMake, the existing execution/timing code, external firmware or deployed EXEs. The first attempted run used a profile directory whose Windows path construction failed; it generated zero profiles and none of its numbers are evidence. A second run without that profile-directory redirection generated seven `.gcda` files. GCC reported missing profile data for the two temporary test-driver sources because the candidate executable name differed; it did not report missing profile data for the five production objects. This is not a fully profile-guided project build or a production qualification.

At the same 10,000,000-instruction, 79,964,294-tick, PC 0003dbc5 checkpoint, the forward baseline/candidate pair took 19,106/17,860 ms and the reverse candidate/baseline pair took 16,780/20,353 ms. This indicates a potential startup-workload gain in two sequential pairs but does not prove complete guest-state equivalence, other widths or workloads.

A further sequential x64 comparison linked those same five optimized objects into the standard product-path private-media diagnostic, leaving all other objects unchanged. Both runs exited zero, sent Enter through the ordinary input API and visually reached World Clock. Baseline and candidate took 372.65 and 372.80 host seconds. At the final sample they had reached 1,079,135,955 and 1,216,406,870 guest ticks and displayed 00:00:32 and 00:00:36, respectively; these are different guest states after equal host time. During the later sample-30-to-36 interval, baseline advanced 186,616,689 guest ticks over 60.404 host seconds; candidate advanced 189,783,869 over 60.223 seconds, approximately 2.0% higher tick throughput. Both clocks remained far below realtime. One ordered pair with frame capture and different guest states does not establish a reliable sustained benefit or equivalence.

The PGO experiment was not adopted: the meaningful steady-workload gain is unproven and small in this run, x86 and other products were not qualified, and adding reproducible training, compiler-specific profile management and cache invalidation would add build complexity. No shortcut, second executor, guest clock substitution, production code or EXE was introduced. The prior S19 712/712 unit gate per width remains the last full repository-only test run; this experiment does not imply desktop/RDP or full receiving qualification.
