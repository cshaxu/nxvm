# T390 S18: M40-C0 Batch Form/Context Disposition

A fresh deleted owner-managed M40-C0 replay reproduces the S17 finite result: 18,255 successful retirements, 75 aggregate rows, zero source-unallocated successes, no fault/status terminal, and the protected-return checkpoint. This confirms the C0 capture is stable enough for matrix work; it does not itself prove an Intel row for any row.

The 75 rows divide into previously named classifier families and generic opcode/escape/group keys. The named families can be reconciled to existing Core timing owners, but the aggregate has two decisive attribution gaps: it does not retain the private source-timing form/owner selected by the classifier, and its generic key intentionally does not retain all ModR/M, operand, branch-outcome, lexical, dynamic or privilege facts needed by every Intel 80386 row. Equal source ticks are not an Intel-primary citation and cannot be used to infer a unique row. Therefore the matrix cannot truthfully be batch-mapped from S17 output alone.

## Disposition

The next receiver is a bounded **shared Core source-form attribution capture** slice. It must add one copied pre-publication attribution to the existing lifecycle-owned retirement observation: the selected private timing-form identifier/owner, plus only those normalized classifier facts needed to distinguish each current source row. It must preserve disabled-path neutrality, reset/failure atomicity and physical nonpublication. It must not expose raw CPU pointers, PC traces or ROM bytes, create a profile-specific classifier, or assign new timings.

After attribution exists, a later T390 batch task must rerun M40-C0, form one complete owner/row/context matrix, cite exact Intel-primary rows and add project-owned regressions for every selected class. Any class without an exact row or required fact transfers as a whole to its named receiver; no one-terminal repair resumes.

This audit neither enables physical retirement nor advances C1, DeskPro board timing, device timing or L3.
