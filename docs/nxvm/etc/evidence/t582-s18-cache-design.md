# T582 S18 — Provider cache design (in progress)

## Confirmed boundaries

The existing `x86_core_cpu_cache_memory` reports decoded address and fill eligibility; the Core currently declares only proven ordinary RAM eligible. A provider can independently implement instruction reads and data reads, so its registration alone cannot prove one shared CPU cache line has identical contents for fetch and data. The PC110 firmware currently has a normal read callback and dynamically selected shadow, Flash and open-bus views. The separate `memory_cache_control` board callback observes admitted external bus cycles and returns status; it does not return KEN/fill eligibility and is not a substitute for a cacheability contract.

A potential generic opt-in must prove the entire 16-byte line resolves to the same provider and physical view, ensure fetch/data equivalence and absence of read side effects, and default every existing unannotated provider to non-cacheable. The 486 write-hit implementation updates its cache after the bus write; where a provider explicitly reports asymmetric read/write views, the line must instead be invalidated after a successful write. This is not solved by the existing provider query alone. The CPU cache line may need a compact per-line write policy, but this is a design candidate, not an admitted implementation or a hardware fact.

PC110 needs to gate any opt-in on its dynamically observed MISCSET and per-region CBL values and the actual internal shadow read mapping. A change in ROMSET, AAXS–FAXS, CBL, MISCSET, SMRAM or firmware backing must invalidate all affected cached physical views and prefetch through the existing ownership path before subsequent guest execution. MISCSET also potentially affects ordinary RAM cache policy, so only guarding the provider range is insufficient to claim a complete chipset cache-enable model. The source mapping of exact CBL field semantics is an L2/L1 model decision, not a VL82C420 vendor-manual formula.

Each candidate must preserve raw overlay/alias/CPU-only/fallback precedence, provider query failure behavior, single-owner execution, DMA snoop and cache-control side effects; no provider read or guest event may be skipped merely for speed. Measure actual late PC110 workload as well as host time and guest progression: real cache hits reduce guest cycle counts, so increased instruction throughput is not automatically improved virtual clock rate. Test asymmetric read/write, dynamic enable/disable, mapping changes, split-line ranges, fetch versus data, reset, DMA and other receivers. The design is intentionally not yet implemented; the exact provider capability, line policy and global control boundaries remain under audit.
