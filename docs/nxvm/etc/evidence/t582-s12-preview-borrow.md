# T582 S12 — lexical-preview cache/TLB borrow

The CPU remains the sole owner of cache and TLB state. A lexical preview on the same serialized owner temporarily borrows that state read-only while retaining its private CPU, decoder and scalar context. It no longer copies the 486 cache and TLB. The private pointer is initialized null in the live context, set only in the synchronous preview copy, never exposed publicly and never reused for diagnostics. Debug register-patch preflight keeps its own existing copied state. CPU bus callbacks may propagate signals but cannot reenter CPU execution or destruction, and observation reads cannot publish device effects.

Existing CPU cache, TLB, Debug state and Machine instruction-preview tests pass on both architectures. The existing cache test compares complete live CPU, decoder and execution context across preview; the TLB test checks cached old mapping, no A/D mutation and rejected Debug preflight rollback. Two assertions explicitly check that the live context holds no preview borrow after these operations. Source and test manifests and NXVM documentation gate pass.

An initial formal-probe comparison placed its EXE and copied CMOS in different directories. PC110 selects CMOS relative to the executable, so the differing guest PC/ticks were caused by different input selection and are invalid for equivalence or performance. The corrected comparison gives each EXE its own adjacent copies and uses the same static-library link order; only the CPU instruction object differs. Both architectures retire 10,000,000 instructions at 79,964,294 guest ticks and PC 0003dbc5. Baseline/current times: x64 23,529/21,977 ms; x86 27,552/26,258 ms. One ordered pair is limited evidence, not an interactive or real-time claim. The earlier S11 product-path comparison used an exploratory candidate rather than this final implementation.

Cached full qualification passed on both widths: 712/712 unit, 48/48 integration and My5160/My5170/DeskPro profile integrations 3/3, 5/5, 6/6. Selected-set MyRaidenII startup and deployed Console probes passed for both widths; these do not prove gameplay or sound. Fourteen receiver EXEs were built and checked for expected PE width; MyNES files were byte-identical. [Artifact inventory](t582-s12-artifacts.json) records hashes. No desktop/RDP interactive acceptance was performed. The original PC110 usability objective remains open.

Tracked production code: 21 additions and 10 deletions (net +11) across three files. Test code: 2 additions and 1 deletion (net +1) in one existing file; manifest, documentation and generated binaries are excluded from these counts. No public API, Lib or Emulator code changed. The pointer is a transient non-owning reference, not a second cache or mirrored machine state. No new production path, retry mechanism or manager was added.
