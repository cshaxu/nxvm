# T582 S21 — Timing input reuse candidate

The completed CPU instruction's prefix count is requested repeatedly by timing helpers. Its implementation calls the existing prefix classification function from a separate translation unit; the source predicate is shared by the decoder and must remain one logical owner. A scratch-only candidate copied that exact predicate into the temporary timing-model translation unit as `static inline`, allowing the compiler to inline the same classification there. It did not modify production code. If a result had warranted a production design, the duplicate scratch predicate would not be shipped; a single private owner, all profile behavior, callers and tests would need review.

A fixed-work PC110 guest probe with private disk/CMOS copies measured each case after 10,000,000 retired instructions. All runs reached 79,964,294 guest ticks and PC 0003dbc5. In baseline-then-candidate order, x64 elapsed 23,334 / 20,793 ms and x86 24,473 / 26,541 ms. In candidate-then-baseline order, x64 candidate / baseline took 21,722 / 19,572 ms and x86 22,214 / 22,986 ms. Thus x64 reversed direction and x86 gains did not reproduce consistently. These are two sequential pairs, not a controlled full-state equivalence test, and differences include host variation. No long World Clock run or correctness qualification is warranted on this evidence; the candidate is rejected. No Shared code, public interface or EXE changed.

This result does not establish realtime PC110 performance or prove that all timing input reuse is unhelpful.
