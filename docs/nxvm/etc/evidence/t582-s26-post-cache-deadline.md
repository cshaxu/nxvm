# T582 S26 — deadline mutation boundaries after provider caching

A scratch-only x64 probe repeated the S13 deadline/access instrumentation against the current S18-era `memory.c` and cached release libraries. The instrumented temporary memory translation unit was generated from the current source; it did not substitute the old S13 implementation. The probe used private CMOS/media copies and stopped at 10,000,000 retired instructions, 79,964,294 guest ticks and PC `0003dbc5`. Counters include the short stop interval and instrumentation perturbs timing.

Of 10,298,272 board-deadline calls, 9,976,519 retained the prior future absolute deadline, 15 moved earlier, two moved later, 321,716 reached or expired it, and 20 were unavailable. All 17 early/late changes coincided with a port access since the previous observation. Among stable calls, 2,282,129 had no port access or counted potentially operational provider read/write or write observer; 7,694,390 had at least one. The probe counted 437,212 port reads, 278,561 port writes, 14,798,512 potentially operational provider read attempts, 1,344,654 provider write attempts and zero write-observer calls. A non-observational provider call is treated conservatively as potentially mutating; this does not prove it actually changed a device. Link wrapping and instrumented call sites do not count uninstrumented routes or establish every possible callback side effect.

The distribution is close to the pre-S18 fixed-work [S13 measurements](t582-s13-scheduler-observation.md); the hypothesis that the existing cache alone would make most intervals clean was not observed in this workload. Identical observed deadlines do not authorize memoization: clock progression, external inputs, DMA, asynchronous callbacks, immediate events and partial failures still require a proven invalidation and ordering contract. The sample is early startup only, x64 only, and not an interactive or World Clock qualification. No production code, interface or executable changed.
