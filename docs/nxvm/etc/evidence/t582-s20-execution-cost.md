# T582 S20 — World Clock execution cost (in progress)

A hidden x64 product-path probe used private copies of PC110 firmware inputs, CMOS and disks, and delivered Enter through the ordinary Machine input API. Its sample-36 screenshot was visually verified as the World Clock page. An instrumented wrapper sampled one in 64 calls to the existing CPU refresh, recording the host `rdtsc` interval and whether each selected call began in ordinary execution, began in SMM, or entered SMM. The timer is diagnostic host-cycle evidence, not guest cycle accounting; sampling overhead, code layout, possible CPU migration and nonsynchronized start/end instructions limit precision. It does not include every instruction or machine-side execution outside refresh.

Between samples 30 and 36 (59.932 host seconds), ordinary-refresh sample cycles increased 866,247,194 across 356,927 samples; SMM-refresh sample cycles increased 304,704,641 across 113,992 samples; SMM-entry sample cycles increased 22,064,557 across 490 samples. Of these sampled refresh intervals, entry accounts for approximately 1.85%, SMM-start 25.5%, and ordinary 72.7%; these are not whole-process CPU percentages. Mean sampled entry cost was about 45,030 TSC units vs 2,427 for ordinary refresh. Both SMM entry and return remain required because firmware issued 28,397 ASMI writes and entered SMM 28,397 times in the interval. The counter classifies by refresh start; an exit instruction belongs to SMM and a transition handled in an ordinary refresh is classified as entry.

This evidence disfavors a claim that the SMM entry alone is responsible for the roughly tenfold slowdown. The prior SMRAM cache candidate also failed to show a sustained improvement; see S19. No production code, public API, firmware, EXE or owner media changed. Native Window/RDP and full app usability were not established by this headless measurement. Scratch log SHA-256: `8A7182D052FB4F27296CF6D55D2A34EA80568848D7E79BE9893D12763C2C30C4`.


A second run additionally measured each call to the existing Machine run function with host `rdtsc` and kept the one-in-64 refresh samples. Between sample 30 and sample 36, Machine-run intervals totaled 118,717,127,996 TSC units; sampled ordinary, SMM and SMM-entry refresh intervals totaled 856,905,219, 324,337,280 and 20,228,298 TSC units respectively. Scaling those samples by 64 gives roughly 76.9 billion TSC units, or about 65% of measured Machine-run intervals; the remaining roughly 35% includes Machine-side timing/device/retirement work and all instrumentation/scheduling effects. The ratio is a coarse exploratory estimate, not precise inclusive accounting: deterministic one-in-64 sampling may alias with guest loops, `rdtsc` is not serialized, and host preemption can add delay. Visual review of the sample-36 screenshot confirms the World Clock page (00:00:28). Guest ASMI remains enabled. No source or artifact modification followed from these estimates. Scratch log SHA-256: `CABB57F1C9EAE42AEC04B7600E361050A4E09B20516BE1C9C77F6A836B8636EB`.


A scratch-compiled copy of the existing CPU implementation, with timing instrumentation around `ExecIns`, timing selection plus observation copy, and `ExecInt`, was linked into a separate private-media diagnostic; it was not used in production. The final sample-36 image was visually confirmed as World Clock (00:00:27). Between samples 30 and 36, the instrumented stage intervals increased by 747,039,886 TSC units for instruction execution, 391,862,433 for timing selection/observation, and 79,704,612 for interrupt dispatch; the separately measured sampled refresh intervals increased by 1,344,610,802 units. Approximate shares within these sampled refresh intervals are 55.6%, 29.1%, and 5.9%, respectively, with the remainder including other refresh work and instrumentation. Stage timers add overhead and can change compiler layout; deterministic sampling and unsynchronized TSC have the limitations above. The timing stage includes the observation copy, so it does not by itself establish cost for any one formula or prove that its calculations can safely be skipped. Scratch log SHA-256: `F31F2FB4989E5DA9A2D6617E1CB0F72E48019AD4B225562F2C77336E5C049CAF`.


A further scratch-only run timed `x86_core_cpu_timing_select` separately from its enclosing timing-and-observation stage. Visual inspection confirmed the sample-36 World Clock page (00:00:26). Across samples 30–36, timing-selection samples increased by 369,096,017 TSC units, compared with 409,590,126 for the enclosing stage (about 90.1%). Instrumentation and deterministic sampling may skew this ratio; the additional nested timer itself contributes overhead. The result directs the audit to the selector rather than assuming the already-reviewed observation copy is the dominant cost. Scratch log SHA-256: `153AEB4A8ED561F4D22C700FFDCA56C7B95187A01D3C2148D50AAF478C1E9BC0`.


One additional scratch run intercepted the existing 80486 source-cost evaluator inside the sampled timing selector. Its sample-36 screen was visually verified as World Clock (00:00:28). Over samples 30–36, the source evaluator accumulated 190,623,230 sampled TSC units and the enclosing selector 413,021,611, roughly 46.2%; the remaining selector time includes generic formula input collection, result construction and nested timer overhead. Each source-evaluator call was intercepted through the existing symbol; there is no product implementation change. Instrumentation, timer nesting, compiler layout and periodic sample aliasing prevent treating the ratio as exact. The existing 486 source model also calls nominal, memory, decode and bus evaluators; any sharing of their decoded inputs must preserve all profile, exception, prefix, metadata and test contracts. S16 already rejected a different prefix-scan microcandidate without demonstrated benefit, so that result must not be presented as evidence for another change.
