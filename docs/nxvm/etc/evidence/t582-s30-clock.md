# T582 S30 — deadline conversion overflow guard

Shared commit `3a2b34d1f` skips the multiplication-overflow division when `delivered_ticks` fits in 32 bits. The clock denominator is also 32-bit, so the product is at most `(2^32-1)^2`, less than `2^64`; larger requests still execute the original overflow guard. Argument validation, result calculation, guest-clock ownership and failure behavior remain unchanged. Production `clock.c` is +2/-1 lines; the existing rational-clock test is +17/-3. The two component manifests have one hash replacement each. No public interface, new state or second clock was introduced.

The existing test now checks the maximum 32-bit request, the first two larger values, the largest valid product, the next overflowing product, unchanged output on failure, and a valid `LIB_UINT64_MAX` identity conversion. The targeted rational-clock test passed on x64 and x86. Both widths then passed 712/712 unit tests, 48/48 default integration tests and selected My5160/My5170/MyDeskPro386 integration tests 3/3, 5/5 and 6/6. MyRaidenII selected-set startup and product-console probes also passed on both widths; those probes do not prove gameplay. All fourteen receiver PE widths were checked in [the inventory](t582-s30-clock-artifacts.json). Ten PC executables and the two MyRaidenII executables changed; both MyNES artifacts were unchanged and matched their build outputs. MyPC110 and MyRaidenII deployed executables matched their build outputs on both widths.

The earlier [S28 candidate experiment](t582-s28-execution-chain.md#clock-deadline-overflow-guard), performed before the S29 shift change, showed faster x64 results in both ordered pairs and mixed x86 results. It did not establish stable cross-width or actual-game speedup. S30 accepts the one-division reduction for the mathematically proven common input range under the owner's clarified criterion; it does not claim a measurable end-to-end gain. No new product-path performance measurement or interactive desktop/RDP validation was performed. T582 and PC110 usability remain open.
