A third hidden run counted SMM transitions around each machine quantum, with a separate private CMOS/media copy. Visual inspection confirmed World Clock at sample 36. Between samples 30 and 36, host time advanced 60.22 seconds and the counter recorded 27,360 SMM entries; the 18,549,712 instructions in quanta that crossed an SMM boundary cannot be attributed solely to SMM. A fourth run wrapped the existing CPU refresh only in the temporary diagnostic and counted the pre-refresh SMM state for each instruction, plus the existing ASMI port call. Between samples 30 and 36, approximately 59.92 host seconds, the trace recorded 21,688,719 non-SMM refreshes and 7,106,180 SMM refreshes, approximately 24.7% of these refreshes in SMM, alongside 27,652 ASMI writes and 27,652 SMM entries. A refresh beginning outside SMM can itself enter SMM, so this is a mode-at-entry count, not a complete host-time attribution. Sampling, frame output and the added per-refresh wrapper perturb performance. Visual review confirmed that the fourth run's sample-36 image shows World Clock (00:00:28).

Existing T580 S47/S48 evidence documents that actual firmware writes port 15EE to request the modelled ASMI service, that the BIOS acknowledges and rearms it, and that startup depends on this guest path. The matching request/entry counts do not establish an erroneous interrupt storm. SMM entry and RSM currently execute a series of four-byte physical accesses through the CPU bus; eliminating or bulk-combining these accesses would require evidence preserving their timing, faults and observable access semantics, so no such change was made.
