# T582 S26 — direct opcode dispatch probe

The current primary instruction executor dispatches through 256 handlers initialized in its instruction table. A scratch generator extracted the 254 fixed assignments into a temporary switch calling the same handlers; opcodes `66` and `67` retained the existing table because their handlers depend on the V30/Intel profile selected during initialization. The existing exception check, instruction semantics and scheduling remained on their normal path. The scratch still contains both the initialization table and generated switch; that duplication is not an acceptable production design. A production proposal would need one authoritative mapping, profile-specific initialization semantics, all-opcode and all-profile equivalence, and actual receiving qualification.

At the fixed PC110 startup checkpoint of 10,000,000 retired instructions, 79,964,294 guest ticks and PC `0003dbc5`, one baseline-then-candidate pair measured 20,457 / 19,938 ms on x64 and 23,693 / 22,993 ms on x86. Candidate executable sizes increased by 9,779 and 10,292 bytes respectively. The roughly 3% differences are comparable to previously observed host and order variation; this early workload is not Game, and matching PC/ticks does not prove full CPU state, exception, V30, Debug or trace equivalence. The probe does not establish a material improvement or justify introducing the duplicate mapping or running the full receiver suite. No production source, interface or EXE changed.
