# T582 S26 — CPU retirement trace candidate

The existing `x86_core_machine_publish_elapsed_ticks` evaluates the CPU linear PC and invokes the existing trace recorder for every retirement, although the recorder returns immediately when no callback is installed. The PC query is a read of CS base plus EIP. A temporary scheduler-source candidate tested checking the existing trace callback before evaluating the trace arguments. Enabled tracing would still call the same recorder; no new state, API, executor or guest timing was introduced. This is a scratch comparison, not a proof of trace equivalence across all registration and reentrant paths.

At the common 10,000,000-instruction, 79,964,294-tick, PC 0003dbc5 checkpoint, baseline/candidate times were 19,202/19,435 ms x64 and 25,576/23,385 ms x86. Reversed candidate/baseline times were 20,120/18,525 ms x64 and 24,975/23,662 ms x86. The second pair reversed the x86 gain and both candidates were slower; these short runs are subject to host noise. There is no demonstrated cross-width improvement, and adding a duplicate trace-admission check is not justified. The candidate was rejected without changing production, interface or EXEs; no long product comparison or extra full suite was run. S19's 712/712 unit results per architecture remain the latest complete repository-only suite.
