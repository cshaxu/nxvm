# T582 S26 — single-tick deadline candidate

Within the existing scheduler loop, when the remaining target interval is exactly one source tick, any positive deadline cannot split that interval further. A scratch-only candidate tested skipping the time/deadline observation for that case while retaining the same scheduler advancement. This did not change the production code, add a timing path or alter the CPU. The current attachment interface does not explicitly establish that its deadline callback may be skipped; the experiment does not prove absence of callback effects, immediate-event, diagnostic, refresh, wait or failure differences. The candidate is therefore not qualified from the arithmetic alone.

At the common 10,000,000-instruction, 79,964,294-tick, PC 0003dbc5 checkpoint, baseline/candidate times were 22,585/22,333 ms x64 and 24,859/23,141 ms x86. Reversed candidate/baseline times were 21,514/21,578 ms x64 and 23,279/22,309 ms x86. The x86 direction reversed and x64 differences were small. These are sequential single pairs and host variation is material. No reliable cross-width gain was shown, so the candidate was rejected without production modification, new tests or long product qualification.
