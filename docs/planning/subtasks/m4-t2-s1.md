# M4 T2 S1: Define Firmware Service Contracts

## Objective

Define Firmware V1 composition, POST, ROM, BIOS interrupt-service, failure,
host-capability, teardown, and trace contracts. The contract replaces the
baseline's global string-table registration model as the M5 target.

## Non-Goals

- Do not write a firmware implementation or migrate baseline source.
- Do not expand BIOS compatibility, implement DOS services, or attach host APIs
  directly to firmware.
- Do not alter fixture images or M1 checkpoints.

## Reference And Evidence

- T1 ownership map: `docs/history/m0-m4/firmware-nxvm.md`.
- Baseline registration: `src/nxvm-baseline/device/vbios.c` and device init
  calls to `vbiosAddPost` and `vbiosAddInt`.
- Machine lifecycle: `src/core/machine.h` and `src/runtime/session.c`.

## Deliverables

- Firmware V1 contracts and migration rules in
  `docs/history/m0-m4/firmware-nxvm.md`.
- `docs/tracking/M4-T2.md` and compact verification record.

## Verification

```text
rg -n "vbiosAdd(Post|Int)|VBIOS_POST_BOOT" src/nxvm-baseline/device
rg -n "firmware_(profile|service|post|rom)|Firmware V1" docs/history/m0-m4/firmware-nxvm.md
rg -n "Win32|CreateThread|CreateWindow|host_open" docs/history/m0-m4/firmware-nxvm.md
git diff --check
```

## Stop Conditions

Stop and escalate if a required BIOS service cannot be expressed through a
Machine/host-capability contract, requires an undocumented platform mechanism,
or demands a DOS service decision.
