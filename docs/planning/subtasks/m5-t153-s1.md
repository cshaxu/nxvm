# M5 T153 S1: Design The Default-Profile x87 Contract

## Objective

Define the smallest correct x87 presence/absence model needed after T152
proved that MS-DOS `MEM` executes `FNINIT` (`DB E3`). Produce the bounded
implementation tasks; do not change execution semantics in this design task.

## Questions To Close

- Whether the default VM profile presents an x87 device to its guest, and how
  an explicitly absent x87 signals fault semantics through the core CPU.
- The ownership split: generic x87 state and escape dispatch belong in
  `core/machine`; the default profile selects capability/presence through an
  existing provider/registry boundary; VM composition binds it.
- The minimum instruction/state set needed for the `MEM` detection path,
  including `FNINIT`, status/control-word observation, reset, and exception
  behavior. Arithmetic emulation and a full 80387 claim are out of scope.
- Project-owned microprobes, the owner-local `MEM` acceptance condition, and
  whether a bounded Bochx comparison is useful for the selected semantics.

## Non-Goals

- No no-op workaround, full x87 arithmetic implementation, generic i386
  capability claim, VDM/DOS-module work, raw trace file, or default Bochx
  dependency.

## Exit

The design names one state owner, one provider/configuration boundary, exact
fault behavior when absent, minimal instruction-family probes, and the T154+
repair breakdown. It records applicable `RULES.md` and CPU-verification
requirements, keeps M6 blocked, and creates no task artifact.
