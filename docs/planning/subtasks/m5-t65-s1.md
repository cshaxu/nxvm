## P2 Full-PC Wrapper Removal

P2 removes the remaining full-PC wrapper singleton rather than relocating it.
`nxvm_full_pc` becomes a caller-owned object containing its active flag,
request transport, and live-machine storage. Every `nxvm_full_pc_*` operation
accepts that object explicitly. `nxvm_product_nxvm_default_profile` and
`vm_composition_full_pc_session` own the corresponding object for their
lifetime; the profile/session APIs may not select a process-global full PC.
Adapter smokes create and destroy their own full-PC object. CPU probe state is
similarly made caller-owned before T65 closes.

Implemented: both `nxvm_full_pc` and `nxvm_cpu_probe` are opaque caller-owned
objects. Their public operations accept the object explicitly; default-profile,
full-PC-session, and adapter-smoke callers retain their own pointer. The former
static full-PC transport/live-machine and CPU-probe live-machine storage are
gone. The retained control-loop singleton remains P3 work because its state is
still selected by executor aliases that T66 through T72 must remove.

Windows GCC/MinGW full build, dependency-DAG, live-machine smoke, and CPU-probe
smoke pass. The FDD DOS-prompt fixture remains unavailable, so T65 remains
active.

## P3 Control-Loop Ownership

The retained VM loop no longer owns process-static control or execution-context
storage. `vm_composition_live_machine` owns `control_storage`, including pause,
run/reset/step flags and its `nxvm_execution_context`; every control operation
now receives that object explicitly. The Console's context, platform sinks,
full-PC wrapper, CPU probe, and debug target all carry the same live-machine
object. This preserves the retained single-live-alias behavior while removing a
second hidden session root.

Windows GCC/MinGW full build, dependency-DAG, live-machine, CPU-probe, and
debug-target smoke gates pass. The FDD DOS-prompt fixture remains unavailable,
so T65 remains active pending its bounded external-media gate. The refreshed
`build/output/nxvm_0_5_0065.exe` has SHA-256
`82712575652F223D92860684217C78AE4E09B6F4F32B38093227A6336D5B4DC4`.

## Objective

Replace the process-global `vm_composition_live_machine` selection mechanism
with a composition-owned VM session context and pass that context through root
composition control and retained command targets.

## Scope

- Map the composition, loop, Console command-target, debugger-target, and
  execution-context callers that presently resolve the current VM session.
- Make a VM session object the explicit lifetime root for the retained full-PC
  storage graph.
- Remove `vm_composition_live_machine_current()` and process-global carrier
  selection without changing individual device aliases yet.
- Add focused session identity/isolation tests and retain all existing full-PC
  compatibility gates.

## Non-goals

- Do not remove `vcpu`, `vram`, device, media, or firmware aliases; those are
  T66 through T71.
- Do not change Console grammar, command behavior, boot/reset order, media
  handling, host threads, DOS behavior, or CPU semantics.

## Required Evidence

- GCC build and `build/output/nxvm_0_5_0065.exe`.
- Dependency-DAG, retained Console/debugger, VM session, and FDD DOS-prompt
  gates.
- A focused proof that session consumers receive an explicit session target and
  that no `vm_composition_live_machine_current()` source reference remains.

## Stop Conditions

Stop if retained Console/debugger behavior requires a global current-session
lookup, if a second machine storage graph is needed, or if command/lifecycle
ordering changes.
