## P2 Full-PC Wrapper Removal

P2 removes the remaining full-PC wrapper singleton rather than relocating it.
`nxvm_full_pc` becomes a caller-owned object containing its active flag,
request transport, and live-machine storage. Every `nxvm_full_pc_*` operation
accepts that object explicitly. `nxvm_product_nxvm_default_profile` and
`vm_composition_full_pc_session` own the corresponding object for their
lifetime; the profile/session APIs may not select a process-global full PC.
Adapter smokes create and destroy their own full-PC object. CPU probe state is
similarly made caller-owned before T65 closes.

Implemented: both `nxvm_full_pc` and `nxvm_cpu_probe` are opaque caller-owned
objects. Their public operations accept the object explicitly; default-profile,
full-PC-session, and adapter-smoke callers retain their own pointer. The former
static full-PC transport/live-machine and CPU-probe live-machine storage are
gone. P3 removes the control-loop singleton; executor aliases remain the
explicit T66 through T72 scope.

Windows GCC/MinGW full build, dependency-DAG, live-machine smoke, and CPU-probe
smoke pass. The FDD DOS-prompt fixture remains unavailable, so T65 remains
active.

## P3 Control-Loop Ownership

The retained VM loop no longer owns process-static control or execution-context
storage. `vm_composition_live_machine` owns the control allocation, including
pause, run/reset/step flags and its `nxvm_execution_context`; every control
operation now receives that object explicitly. The Console's context, platform
sinks, full-PC wrapper, CPU probe, and debug target all carry the same
live-machine object. The control and debug-target allocations remain session
owned, and the NXVM entry point allocates the full live-machine graph on the
heap rather than the near-limit 1 MiB process stack. This preserves the
retained single-live-alias behavior while removing a second hidden session root.

Windows GCC/MinGW full build, dependency-DAG, retained Console, live-machine,
CPU-probe, and debug-target smoke gates pass. The refreshed
`build/output/nxvm_0_5_0065.exe` has SHA-256
`7BEB8AB27B1AA2B922E361AF08BC3D3DD755E0AA8D064E8E3C09D2FA95266E8A`.

## P4 Bounded FDD Regression

The owner-provided `D:\home\repos.hobby\fdd.img` is now available and must
match the M1 fixture identity before launch. The test drives the retained
Console with the FDD image, records only to the ignored unique path
`build/t65-fdd-session.trace`, and runs for at most 10 seconds. The trace has
a hard 512 MiB budget, matching the historical M1 ten-second trace scale; the
harness checks size while the process runs, stops
the VM through its Console command boundary, waits for process exit, records
the final checkpoint, and deletes the raw trace. The harness owns every
launched process and must terminate it on timeout or budget excess.

An initial 128 MiB attempt exceeded its budget because this host's legacy
recorder writes faster than the monitor interval and its unsupported process
tree-kill overload prevented prompt cleanup. It produced no `INT 21h`
checkpoint and its raw trace was deleted. It is diagnostic failure only, not
regression evidence; the replacement uses the PowerShell-compatible owned
process termination path.

The corrected run matched the FDD fixture SHA-256 and size, ran for its full
10-second watchdog budget, kept the trace to 150,564,058 bytes, and recorded
`INT     21`. The owned process was then terminated by the watchdog with exit
status `-1`; its trace handle was closed and the raw trace deleted. This is the
same bounded-progress verdict as the M1 fixture record, not a claim of natural
guest completion.

## Objective

Replace the process-global `vm_composition_live_machine` selection mechanism
with a composition-owned VM session context and pass that context through root
composition control and retained command targets.

## Scope

- Map the composition, loop, Console command-target, debugger-target, and
  execution-context callers that presently resolve the current VM session.
- Make a VM session object the explicit lifetime root for the retained full-PC
  storage graph.
- Remove `vm_composition_live_machine_current()` and process-global carrier
  selection without changing individual device aliases yet.
- Add focused session identity/isolation tests and retain all existing full-PC
  compatibility gates.

## Non-goals

- Do not remove `vcpu`, `vram`, device, media, or firmware aliases; those are
  T66 through T71.
- Do not change Console grammar, command behavior, boot/reset order, media
  handling, host threads, DOS behavior, or CPU semantics.

## Required Evidence

- GCC build and `build/output/nxvm_0_5_0065.exe`.
- Dependency-DAG, retained Console/debugger, VM session, and FDD DOS-prompt
  gates.
- A focused proof that session consumers receive an explicit session target and
  that no `vm_composition_live_machine_current()` source reference remains.

## Stop Conditions

Stop if retained Console/debugger behavior requires a global current-session
lookup, if a second machine storage graph is needed, or if command/lifecycle
ordering changes.
