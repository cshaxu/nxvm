# M5 T155 S1: Centralize CPU Profile Gating

## Objective

Replace the unconditional legacy `i386(n)` compatibility shim with one decoder
gate driven by T154 form metadata and the frozen `core_machine` CPU profile.

## Scope

- Reject unavailable primary/`0F`/prefix forms through the existing `#UD` path
  before operand decode or guest-visible side effects.
- Preserve documented 8086 `POP CS` handling for primary `0F`; reject later
  `0F` extensions in `8086`.
- Prove positive base-8086 execution and negative 80186, 80286, and 80386 form
  probes. Retain default `80386` behavior and existing DOS boot.

## Non-Goals

No FPU ESC behavior change, present-FPU implementation, CPU hot switch,
protected-mode completion, paging completion, or Console syntax change.

## Exit

No `i386(n) if (1)` remains. One metadata-driven gate is the only CPU-profile
availability decision in the decoder, with bounded positive/negative probes
and retained GCC/Console/FDD evidence.
