# M5 T156 S1: FPU ESC Absence And FWAIT Behavior

## Objective

Replace direct `D8`--`DF` undefined-opcode dispatch with a core-owned FPU ESC
dispatcher. For `FPU=none`, it consumes a complete escape encoding and
continues unless CR0 `EM` or `TS` requires `#NM`. Repair FWAIT to use `TS && MP`.

## Scope

- Use T154 FPU metadata and per-machine frozen profile state.
- Consume the opcode, ModRM, and any addressing displacement without memory or
  arithmetic side effects in the `none` path.
- Route configured present-FPU forms to one explicit unsupported-FPU diagnostic
  path, never `#UD`; product UI selection remains deferred to T157.
- Correct `#NM` text and add bounded ESC/FWAIT probes, including the owner-local
  `MEM` observation past `FNINIT`.

## Non-Goals

No x87-named API, full present-FPU operation/state, raw tracing, CR0 feature
completion, or user-facing session syntax.

## Exit

No `D8`--`DF` direct `UndefinedOpcode` mapping remains. Default `80386+none`
passes `FNINIT` and retains GCC, Console, debugger, and FDD boot evidence.
