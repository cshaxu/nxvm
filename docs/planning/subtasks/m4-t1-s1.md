# M4 T1 S1: Assign Full-PC Ownership

## Objective

Produce the versioned ownership and migration map for every retained NXVM
whole-PC unit. Assign each unit to `core`, `firmware`, `platform`,
`products/nxvm`, or a temporary baseline adapter, and state its M5 migration
order and regression owner.

## Non-Goals

- Do not move source, change a BIOS service, or add a new nxvm process CLI.
- Do not define DOS loader or ntvdm64 platform behavior.
- Do not import guest media, Microsoft binaries, or external code.

## Reference And Evidence

- M3 snapshot and M4 inputs: `docs/planning/m4-design-inputs.md`.
- Baseline composition: `src/nxvm-baseline/device/vmachine.c`.
- Baseline firmware construction: `src/nxvm-baseline/device/vbios.c`.
- M1 fixture and watchdog evidence: `docs/verification/m1-t2-s1-nxvm-baseline.md`.

## Deliverables

- `docs/requirements/firmware-nxvm.md` ownership map and migration order.
- `docs/tracking/M4-T1.md` decision and evidence index.

## Verification

```text
rg -n "(Init|Reset|Refresh|Final)\\(" src/nxvm-baseline/device/vmachine.c
rg -n "vbiosAdd(Post|Int)|deviceConnect" src/nxvm-baseline/device src/nxvm-baseline/console.c
rg -n "firmware|products/nxvm|baseline adapter" docs/requirements/firmware-nxvm.md
git diff --check
```

## Stop Conditions

Stop and escalate if ownership requires a new DOS ABI, a concrete host API in
`firmware`, a protected asset, or an undocumented Windows behavior.
