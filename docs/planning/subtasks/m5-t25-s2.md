# M5 T25 S2: RAM And A20 Authority Migration

## Objective

Move the retained full-PC RAM/A20 implementation into canonical
`core/machine/memory.*`, with one embedded `t_ram` in the VM live-machine
carrier. All compatibility access must dereference that object directly.

## Required Order

1. Move the M3 minimal-memory implementation out of `memory.c` beside
   `machine.c`, retaining its `nxvm_core_machine_memory_*` test API.
2. Use `git mv` to move `vram.c/.h` into canonical `memory.c/.h`; repair
   direct includes and the core-machine CMake target before moving another
   source file.
3. Embed `t_ram ram_storage` in `vm_composition_live_machine`; bind
   `core_machine_memory_current()` to it. The temporary `vram` spelling may
   only be a direct current-object alias.
4. Preserve existing port `0x92` callback registration through the retained
   `vport`, PIT channel-1 registration, 16 MiB initial allocation, reset,
   refresh, and finalization order. Port ownership is T26, not T25.
5. Switch direct callers in small groups: composition/tests, CPU physical
   access, DMA, then default-profile firmware. Each group must still name the
   same `ram_storage` bytes.

## Required Verification

- Add a focused RAM authority smoke proving the live carrier and compatibility
  accessor identify the same object; verify A20-off aliasing, A20-on separation,
  and the historical high-ROM read mirror.
- Preserve the independent minimal-machine memory-instance smoke.
- Build GCC, dependency-DAG, CPU stop/probe, debugger target, full-PC FDD/HDD
  profile, and retained Console `HELP`/`EXIT` gates.
- Manually retain the established FDD DOS-prompt checkpoint before accepting
  the task; the reset-vector smoke does not replace it.
- Build `build/output/nxvm-m5_t25.exe` only after all runtime gates pass.

## Stop Conditions

Stop if any step needs copied RAM, a second allocation, changed A20 wrapping,
changed high-ROM mapping, changed lifecycle order, a core-to-VM dependency, or
any retained Console/debugger/boot regression.

## P1 Result

Complete. `vram.c/.h` now live as canonical `memory.c/.h`; the independent M3
minimal-model source is `machine_memory.c/.h`. The VM live carrier embeds the
sole full-PC `t_ram` and `vram` is a direct current-object alias. GCC and all
automated authority, A20, CPU, debugger, full-PC profile, Console, and DAG
gates pass. P2 is closed by owner-observed FDD DOS-prompt acceptance for T25
through T31.

## P2 Observation Boundary

An existing-Console scripted `DEVICE FDD INSERT`, `START`, delayed `STOP`, and
`EXIT` observation exceeded its 60-second host bound without a prompt on
capturable stdout; its owned process was terminated. This remains the recorded
unreliable scripted-stop boundary, not prompt evidence. The owner has since
observed the actual FDD DOS prompt for T25 through T31, closing this manual
checkpoint; do not reinterpret the scripted timeout as a boot result.
