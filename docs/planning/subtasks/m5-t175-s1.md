# M5 T175 S1: VM Session Owner-Alias Closure

## Objective

Make every embedded VM session object its own direct field, deleting the
permanent `*_storage`/same-object pointer aliases. Keep `core_machine` opaque
and separately owned; retain `debug_target` only as an explicit lazy dynamic
allocation if its lifecycle remains necessary.

## Ownership Decision

`vm_session` directly owns every object presently named `*_storage`; its
final field name is the object name without `_storage`. A caller passes its
address explicitly, for example `&session->fdd`. It cannot be rebound.

Only these pointers remain after closure:

- `core_machine *core_machine`: separately allocated opaque core with explicit
  `core_machine_create`/`core_machine_destroy` ownership.
- `core_product_debug_target *debug_target`: lazy debugger UI adapter with
  explicit allocation and `vm_session_debug_target_finalize` teardown.

`control` is directly embedded. It contains atomics and an execution context,
but owns no separately allocated resource; its existing initialize/finalize
functions establish/reset state and remain the sole lifecycle API.

## Implementation Breakdown

| Task | Owner group | Required evidence |
| --- | --- | --- |
| T176 | presentation mailbox, execution/keyboard transports, wait scope | mailbox, input, wait-scope smokes |
| T177 | platform run context and run handle | Console/window stop/join and multi-window smokes |
| T178 | debugger context and lazy target boundary | Console `DEBUG`, debugger-target and lifecycle smokes |
| T179 | CMOS and VM debug device | reset, pause/trace/record smokes |
| T180 | FDD, HDD, FDC | explicit media commands and FDD DOS-prompt smoke |
| T181 | BIOS, QDX, default-profile context | reset-vector, QDCGA, keyboard firmware smokes |
| T182 | block, keyboard, display provider slots | freeze, display, keyboard and two-session isolation smokes |
| T183 | embedded control state | pause/step/continue/stop and worker teardown smokes |
| T184 | closure scan and full owner/lifecycle review | GCC, source scan, Console, debugger, FDD prompt artifact |

Each task changes one owner group only, removes its aliases from both the
struct and initialization/finalization, and immediately compiles before the
next task begins.

## Rules And Gates

Applicable `RULES.md`: one mutable-state owner, no permanent same-object
aliases, explicit dynamic ownership, composition-only integration, retained
Console/debugger/FDD behavior, one active subtask, task artifact, and build
hygiene. T175 is design-only and creates no artifact; T176--T184 each create
their task artifact after their applicable GCC and behavior gates pass.

## Non-Goals

No Console grammar, debugger UX, startup, media policy, thread model,
multi-session behavior, CPU/device behavior, or VDM change.

## Stop Conditions

Stop on a changed lifecycle order, a second state allocation, a stale pointer,
any user-visible behavior change, or failed FDD prompt.
