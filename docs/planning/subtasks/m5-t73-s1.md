# M5 T73 S1: Legacy Selection Closure

Status: active.

## Objective

Delete the final mutable selected-session globals and legacy `v*` aliases.
Every retained execution path must receive the composition-owned object graph
explicitly; two independently initialized sessions must not cross-write.

## Migration Order

1. Convert `vm/composition.c` lifecycle, refresh, and machine-info paths to
   its existing live-machine fields; it is the final VM product consumer.
2. Delete obsolete core device wrappers after their callers use explicit RAM,
   port, CPU execution, PIC, PIT, DMA, KBC, and VADP objects.
3. Replace firmware-local compatibility spellings with context-aware helpers;
   profile firmware may not select a session.
4. Delete CPU/decoder current-object accessors and the legacy bind sequence
   from live-machine composition.
5. Add a two-session isolation smoke, run the closure scan, retained Console
   and debugger gates, and the three-second FDD boot-and-host-display gate.

## Hard Gates

- No copied guest state, second executor, or changed Console/debugger grammar.
- `src/core` never depends on VM or VDM.
- No source declaration, macro, or call remains for the selector names listed
  in `m5-instance-authority-plan.md`.
- The final `0.5.0073` artifact is created only after all closure gates pass.

## P1 Evidence

`vm/composition.c` now uses its live-machine CPU execution, RAM, and port
objects directly for initialization, reset, refresh, finalization, and machine
information. The RAM initialization preserves the legacy PIT channel 1 gate
side effect explicitly. CPU initialization uses `core_machine_cpu_state_initialize`,
not the narrower executor-only initializer; that distinction was verified by
the three-second boot/display gate. Retained Console/debugger, full-authority,
and boot/display gates pass.

## P2 Evidence

Removed unreferenced CPU, RAM, and port lifecycle/physical-access legacy
wrappers after P1 moved their only VM composition caller. Empty refresh calls
were removed. The explicit RAM path continues to register A20 ports and enable
the historical PIT channel 1 gate. Full-authority, strengthened boot/display,
and debugger-target gates pass.

## P3 Evidence

Default-profile BIOS assembly, BIOS data area, IVT, ROM-info, and disk
parameter-table writes now take the reset caller's RAM object explicitly.
The shared real-address helper now applies the RAM object's A20 policy before
wrapping by size, matching the former macro behavior. BIOS authority and the
strengthened FDD boot/display gates pass.

## P4 Evidence

Default-profile CGA firmware now reads CPU, RAM, and video-adapter state from
its `vm_profile_default_context`. Its video-memory and real-address accesses
go through the explicit RAM object; no firmware-local `vcpu`, `vram`, or
`vvadp` compatibility aliases remain. QDCGA boundary, full-authority, and
strengthened FDD boot/display gates pass.

## P5 Evidence

CPU execution and its decoder no longer expose mutable selected-session
objects. CPU inspection, linear access, segment loading, and watchpoints take
the explicit execution context; the VM debugger passes its composition-owned
context. Historical smoke assertions now verify those same owned fields rather
than a global alias. A full GCC build, CPU authority/stop, debugger target,
full-authority, and strengthened FDD boot/display gates pass.
