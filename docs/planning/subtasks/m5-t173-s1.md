# M5 T173 S1: Retain VM Session During RAM Cold Reconfiguration

## Objective

Route the retained `DEVICE RAM` command through the stopped-only core operation
from T172. Delete the temporary T165 whole-session reconstruction path.

## Boundary

The existing `vm_session`, `core_machine`, FDD/HDD, debugger, platform context,
session ID, media mounts, and Console grammar remain intact. The operation is
rejected while the VM control is running or a platform run handle is active.
Only the core RAM backing changes; the core cold reset establishes the normal
stopped cold-start state.

## Rules And Evidence

Applicable `RULES.md` checks: one state owner, stopped-only core mutation,
provider topology remains frozen, no raw RAM backing access, retained NXVM
Console/debugger/FDD behavior, and one task artifact. The session smoke proves
identity preservation and reset-vector recovery. GCC build, retained Console
lifecycle, and FDD DOS-prompt gates are required.

## Non-Goals

No command grammar change, media policy change, platform-handle redesign,
session cloning, CPU/FPU/profile hot reconfiguration, or VDM behavior.

## Stop Conditions

Stop on session/core/device/platform/debugger replacement, an active-handle
reconfiguration, lost media, changed Console behavior, or failed FDD prompt.
