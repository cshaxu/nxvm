# M3 T1 S2: Create Machine Instance Shell

## Objective

Extend Shared Core V1 so each opaque Machine owns independent CPU reset state,
range-checked RAM, and a session-local I/O port dispatch table. The public
surface exposes only checked operations and snapshots; it never exposes the
legacy global structures or a writable RAM pointer.

## Non-Goals

- Do not move or alter the imported `src/nxvm-baseline/` CPU, RAM, port, BIOS,
  device, platform, Console, or boot-loop code.
- Do not execute guest instructions through the new core yet.
- Do not implement interrupts, firmware, DOS services, product profiles,
  host APIs, or final debugger behavior.
- Do not claim that the isolated Machine shell is already the M1 full-PC
  runtime.

## Reference Baseline And Transition

- M1 source snapshot: `6d6b7d70ab6ed83ab973d27aeea6db88f4e87e4f`.
- The imported `vcpu`, `vram`, and `vport` modules remain byte-preserved
  single-instance legacy state until later M3 profile composition work.
- The new `core` shell is the replacement owner for new code. The untouched
  baseline executable remains the temporary full-PC regression adapter, so its
  FDD/HDD checkpoint evidence remains attributable to the M1 baseline rather
  than to an unverified partial port.

## Files And ABI Surface

- `src/core/cpu.h`, `src/core/cpu.c`
- `src/core/memory.h`, `src/core/memory.c`
- `src/core/port.h`, `src/core/port.c`
- `src/core/machine.h`, `src/core/machine.c`, `src/core/machine_impl.h`
- `tests/core/machine_instance_smoke.c`
- `CMakeLists.txt`, `CMakePresets.json`
- `src/adapters/nxvm_baseline/README.md`

The core owns each CPU/RAM/port implementation privately. RAM reads/writes are
checked; A20 behavior is explicit; port callbacks receive a private owner
context and may not expose the Machine's internals. The initial CPU reset state
matches the retained baseline reset vector (`F000:FFF0`) as a deterministic
contract, not as a boot compatibility claim.

## Verification

Run:

```text
cmake --preset mingw-gcc-x64
cmake --build --preset m3-machine-instance-gcc
build/mingw-gcc-x64/nxvm-core-machine-instance-smoke.exe
cmake --build --preset m1-baseline-gcc
rg -n "windows.h|win32|Win32|INT 21|ntvdm64 run|products/|nxvm-baseline" src/core tests/core
git diff --check
```

Expected markers:

- instance smoke prints `M3:T1:S2:MACHINE-INSTANCE:OK`;
- two Machine instances retain independent CPU/RAM/port state;
- reset exposes `F000:FFF0`, initialized flags, and cleared RAM/port state;
- the retained M1 baseline still builds without source modification;
- forbidden dependency scan produces no matches.

## Budgets And Stop Conditions

The deterministic core smoke has no guest execution loop. The baseline build
has no guest-media requirement; the recorded FDD/HDD evidence remains the M1
ten-second watchdog record until T3 introduces a shared-core full-PC profile.

Stop and escalate if an instance API requires a legacy global pointer, a raw
RAM pointer, a host/platform type, an ABI-incompatible source move, or a
pointer-width/aliasing defect changes the preserved M1 baseline.
