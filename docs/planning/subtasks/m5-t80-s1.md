# M5 T80 S1: Console Run Context

Status: complete.

## Objective

Implement C1 from the T79 migration map. Give the Win32 Console kernel,
display, and input work one explicit composition-owned run context instead of
process-global execution and keyboard sink lookups.

## Non-Goals

Do not change the Win32 window path, Linux runtime path, display mailbox,
mode/handle ownership, or wait-provider scope. Do not alter NXVM Console
commands, debugger behavior, boot/reset order, or guest execution.

## Baseline And Scope

Baseline: `f97ccfd`. The context may contain only non-owning host adapter and
transport references plus Console handles. It must not copy or own CPU, RAM,
ports, devices, profile state, or guest execution state. The composition
creates and retains it for the host run; Console threads receive it through
their `LPVOID` argument.

## Gates

1. Build the GCC `nxvm` target and relevant focused tests.
2. Run the retained Console command and keyboard-transport tests.
3. Run `nxvm-vm-dos-prompt-smoke D:\fdd.img` and retain
   `M5:T70:S2:DOS-PROMPT:OK`.
4. Do not create a T80 artifact: artifacts are task-level, and T80 remains
   active until C1--C6 all close.

## Stop Conditions

Stop for owner review on a changed Console/debugger interaction, boot/reset
ordering change, copied guest state, a second execution loop, a failed FDD
gate, or any required change to the unscoped window/Linux paths.

## Result

Console kernel, display, and input threads receive a shared
`vm_platform_run_context` through `LPVOID`. Its live-machine-owned keyboard
and execution transports are verified isolated by focused smokes. The retained
global transport APIs remain only for C2/C3's unscoped window/Linux paths.
GCC build, Console, facade, and FDD DOS-prompt gates passed. No task artifact
is published until all T80 cutovers close.
