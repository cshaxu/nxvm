# M5 T105 S1: VM Product, Profile, And Adjacent API Naming

Status: complete.

## Objective

Normalize VM product and profile APIs, plus adjacent legacy composition and
platform prefixes discovered in their active call paths, to their real
`vm_product_*`, `vm_profile_*`, `vm_composition_*`, and `vm_platform_*`
owners.

## Non-Goals

- Preserve the existing NXVM Console grammar, debugger, profile selection,
  boot/media behavior, and provider bindings.
- Do not move source files or retain compatibility aliases.

## Verification

Active source/tests must have none of `consoleMain`, `nxvm_product_nxvm_*`,
`nxvm_vm_*`, or `nxvm_full_pc_*`; build `nxvm_0_5_0105.exe`, all GCC gates,
FDD DOS prompt, and retained Console.

## Result

VM product, profile, composition, and request-transport APIs now use their
actual source-owner prefixes. The historical reset-vector name collision was
resolved by keeping full-PC and default-profile vector types distinct.
Evidence is `docs/verification/m5-t105-s1-vm-product-profile-api-naming.md`.
