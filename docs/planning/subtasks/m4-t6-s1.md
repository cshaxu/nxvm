# M4 T6 S1: Define CPU Correctness And Bochx Verification

## Objective

Record the current partial i386 risk, define profile CPU capability claims and
the `#UD` triage contract, and specify the optional local Bochx/Bochs
differential bridge before M5 migrates CPU-adjacent code.

## Non-Goals

- Do not fix an instruction, import Bochx or Bochs code, or add a default
  build dependency.
- Do not commit MS-DOS 6.22 media, a Bochs tree, Bochs patches, or trace data.
- Do not claim complete 80386 conformance.

## Reference And Evidence

- Baseline invalid-opcode path: `src/nxvm-baseline/device/vcpuins.c`.
- Historical local bridge: sibling `../nxvm/bochx/README`, `bochsapi.h`, and
  `nxvmapi.c`, read-only research inputs.
- Existing trace boundary: `docs/governance/differential-debug-policy.md`.

## Deliverables

- CPU capability and Bochx policy in `docs/requirements/cpu-verification.md`.
- Revised profile, source, differential-debug, roadmap, and M5 breakdown
  contracts.

## Verification

```text
rg -n "partial|#UD|Bochx|Bochs|i386" docs/requirements/cpu-verification.md docs
rg -n "BOCHSAPI|bochsApiExec(Before|After)" ../nxvm/bochx
git diff --check
```

## Stop Conditions

Stop and escalate if the design would import or patch Bochs in this repository,
make a reference CPU a runtime dependency, claim unproven i386 coverage, or
use protected guest media as a committed fixture.
