# M5 T70 S1: VM Machine Provider Authority

Status: active.

## Objective

Remove the VM machine providers' selected-object aliases without changing the
full-PC boot, reset, refresh, media, Console, or debugger behavior. Each device
keeps the one storage object in `vm_composition_live_machine`; callbacks receive
the real object or a small non-owning dependency context.

## Ordered Parts

1. **CMOS:** pass CMOS, CPU, and port ownership explicitly; make RTC refresh
   time session state; delete `vcmos` and its current/bind helpers.
2. **HDD:** pass the media object directly to allocation, transfer, format,
   and file operations; delete `vhdd`.
3. **FDD/FDC:** bind FDD, FDC, DMA, PIC, and port references explicitly in typed
   callbacks; delete `vfdc` only after every port/DMA path is moved.
4. **Debug:** bind debug state to the CPU execution context and pause target;
   delete `vdebug` only after retained Console/debugger callbacks are direct.
5. **Composition and diagnostics:** replace lifecycle, `INFO`, and smoke
   callers with direct live-machine fields; rebuild the task artifact and run
   the full T70 gate set.

## P1 Evidence

CMOS no longer has a current-object pointer, bind/unbind helper, or `vcmos`
macro. Its port handlers receive the CMOS object as their registered owner and
use the composition-owned CPU/port references. The one-second RTC suppression
timestamp is now stored in that CMOS instance rather than as a process static.
The CPU probe, full-PC session, and FDD/HDD profile gates pass. The former
CMOS authority smoke now verifies direct composition storage ownership.

## P2 Evidence

HDD no longer has selected-object storage, a current/bind/unbind API, or the
`vhdd` macro. Lifecycle, Console media commands, full-PC configuration, and
machine information pass the composition-owned HDD object directly. The legacy
DMA transfer helpers are now explicit HDD/latch operations even though the
retained stateless HDC does not currently invoke them. HDD authority,
full-authority, full-PC session, and FDD/HDD profile fixture gates pass.

## P3 Evidence

Core DMA now has an owner-aware device callback slot. Its read, write, and
close callbacks receive the registered provider owner and the live DMA latch.
The retained no-context callback fields are an explicitly temporary fallback
for the unconverted FDC only; no new caller may use them. RAM/port context,
full-PC session, and FDD/HDD profile fixture gates pass before FDC switches to
the new slot.

## P4 Evidence

FDD now exposes explicit media, transfer, format, lifecycle, and file-I/O
operations over a supplied `t_fdd` object. The retained FDD facade remains
only because the unconverted FDC still drives its DMA/port transfer sequence.
P5 must move that sequence to the explicit FDD API and DMA owner slot before
the FDD facade may be deleted.

## P5 Evidence

FDC now records the composition-owned FDD, DMA latch and controller pair, PIC
pair, and port bus as non-owning links before the retained device lifecycle
begins. The FDC authority smoke verifies object identity for every link rather
than asserting the transitional selected-object alias. This part changes no
FDC command, port-handler, DMA callback, reset, or Console behavior; P6 will
thread the FDC owner through those paths and remove the selected-object layer.

## P6 Evidence

FDC port handlers and DMA callbacks now receive their owning `t_fdc` and use
only its P5 non-owning links. Its command, reset, refresh, lifecycle, and
diagnostic operations accept an explicit FDC object; composition calls those
operations directly. `vfdc` and its current/bind/unbind API are deleted.
The FDC authority, full-PC session, full-PC profile, and retained-Console FDD
`insert -> start` survival gates pass.

## P7 Evidence

FDD lifecycle, media creation and I/O, Console media commands, full-PC setup,
diagnostics, and regression callers now pass the composition-owned `t_fdd`
directly. Its selected-object storage, current/bind/unbind API, aliases, and
duplicate legacy transfer implementation are deleted. FDD/FDC authority,
full-authority, pause-boundary, unified-debugger, and retained-Console FDD
`insert -> start` survival gates pass.

## Hard Gates

- No provider may copy media, CPU, RAM, DMA, PIC, port, or debug state.
- A callback must receive a typed owner/context; it must not select a machine.
- Port registration and lifecycle order remain exactly as the retained full PC.
- T70 does not begin profile firmware migration; BIOS/QDX consumers remain
  assigned to T71.
- T70 closes only when `vcmos`, `vfdd`, `vfdc`, `vhdd`, and `vdebug`, including
  their current/bind/unbind APIs, have no source declaration or call.
- Every T70 artifact must pass the fixture-backed retained-Console FDD
  `insert -> start` survival probe recorded by M5 T68 S2.
