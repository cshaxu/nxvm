# M5 T154 S1: CPU/FPU Profile State And Form Metadata

## Objective

Add frozen per-machine CPU/FPU profile state and a local opcode-form metadata
surface without changing dispatch behavior. The legacy unconditional decoder
remains only until T155 installs the centralized CPU gate.

## Scope

- `core_machine_config` accepts CPU `8086`/`80186`/`80286`/`80386` and FPU
  `none`/`8087`/`80287`/`80387` choices; zero-initialized compatibility config
  resolves to `80386+none`.
- `core_machine` owns the resolved CPU profile and an instance-owned FPU
  skeleton. Its execution context receives copied frozen values.
- `core_machine_cpu_instruction_metadata_get()` classifies primary, `0F`, and
  FPU-escape forms by minimum CPU/FPU or illegality. ModRM-selected `0F`
  groups classify their valid sub-forms individually.
- The FPU skeleton has no arithmetic/state emulation and does not alter
  existing `D8`--`DF` dispatch. T156 owns that behavior change.

## Verification

- `nxvm-core-machine-cpu-fpu-profile-smoke` constructs every CPU/FPU pair,
  proves default resolution, and probes representative `80186`, `80386`, FPU,
  and post-80386 metadata.
- Retained GCC, Console, debugger, and FDD DOS-prompt gates run before close.

## Exit

The next task may use one frozen context profile and one metadata source to
gate execution. No profile is user-selectable yet, and no present FPU profile
is claimed usable.
