# M5 T51 S1: Interface And Provider Naming Audit

Status: complete.

## Objective

Audit remaining public/provider contract names and split or rename only the
files whose current names obscure ownership enough to create future migration
risk.

## Scope

- Inspect core machine, core platform, and core product headers for mixed
  interface/provider ownership.
- Identify headers where `*_interface.h` and `*_provider.h` should be separate
  before implementation.
- Apply only low-risk renames or splits that preserve function behavior,
  callback order, provider lifetime, and build target ownership.
- Complete T51 by producing `build/output/nxvm_0_5_0051.exe` only if runnable
  paths changed.

## Non-goals

- No guest behavior change.
- No provider lifetime change.
- No new host capability or product policy.
- No removal of retained `v*` runtime aliases.
- No platform migration, DOS, CLI, CPU instruction, or multi-session work.

## Verification

1. Configure and build the GCC CMake tree. Passed.
2. Run affected focused provider/interface smokes. Passed.
3. Run dependency-DAG/source-root checks. Passed.
4. Run retained Console smoke if any runnable path changed. Passed.
5. Copy and hash `build/output/nxvm_0_5_0051.exe`. Passed.

## Result

- `core/machine/block_interface.h` now exposes block operations and geometry;
  injected callbacks live in `core/machine/block_provider.h`.
- `core/product/wait.h` now exposes wait use; injected wait callbacks live in
  `core/product/wait_provider.h`.
- Core firmware public symbols now use `core_machine_firmware_*` and
  `CORE_MACHINE_FIRMWARE_*`.
- No provider lifetime, callback order, Console, debugger, or guest behavior
  changed.

## Stop Conditions

Stop if the audit shows a split would require changing callback order,
provider lifetime, guest state mutation, Console/debugger UX, or non-mechanical
implementation behavior.
