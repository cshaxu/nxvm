# M5 T159 S1: Core Lifecycle Boundary Audit

## Objective

Confirm and permanently guard the T141 lifecycle boundary: no VM or VDM device
may initialize, reset, refresh, or finalize a generic core device between core
device phases.

## Confirmed Model

The only supported order is:

```text
core_machine_create
  -> composition creates VM/VDM-only objects
  -> composition binds providers, firmware, and VM/VDM-only devices
  -> core_machine_freeze_execution_providers
  -> core_machine_reset
  -> core_machine_run
  -> composition finalizes VM/VDM-only objects
  -> core_machine_destroy
```

`core_machine` owns CPU, RAM, port, PIC, PIT, DMA, KBC, VADP, and FPU storage
and lifecycle order. A VM/VDM object may borrow a core capability during its
own binding phase, but may not insert its lifecycle between core-device
initialization, reset, refresh, or finalization calls. A dependency that cannot
fit this model is either a core device or requires a separately approved fixed
provider boundary; it may not create an ad hoc composition ordering rule.

## Scope

- Audit the actual VM/VDM source paths against the confirmed model.
- Add a repository-owned static gate rejecting direct generic core-device
  lifecycle calls below `src/vm` and `src/vdm`.
- Remove stale TODO claims and misleading composition-only historical markers.
- Preserve existing lifecycle order, NXVM Console/debugger, and FDD boot.

## Non-Goals

No new lifecycle callback phase, device move, VM/VDM feature, FPU operation,
or M6 DOS work.

## Exit

The source gate, GCC build, Console/debugger, and FDD prompt checks pass.
Produce `build/output/nxvm_0_5_0159.exe` and record the actual ownership map.
