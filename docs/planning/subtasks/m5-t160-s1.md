# M5 T160 S1: Public Lifecycle Hardening

## Objective

Make the public `core_machine` lifecycle enforce the existing single-owner
model: configure providers, freeze once, reset, run bounded quanta, then
destroy. Reject topology and externally mutable guest-state operations outside
their defined boundary.

## Scope

- Permit execution/port provider binding only in `INITIALIZED` before freeze.
- Require the one-time provider freeze before reset.
- Require `PAUSED` for public physical-memory, port, and A20 operations.
- Preserve provider callback order and VM/VDM composition ownership.
- Add a focused configuration-order smoke and keep CMake's current artifact
  preset truthful.

## Non-Goals

No new execution loop, device move, provider phase, UI change, CPU behavior,
or VDM runtime path.

## Rules And Gates

Applicable `RULES.md` rules: one core-machine executor/lifecycle owner,
frozen topology before execution, explicit session boundaries, retained NXVM
behavior, and task artifact hygiene.

Run Windows GCC build plus:

1. `nxvm-core-machine-lifecycle-contract-smoke` ->
   `M5:T160:S1:LIFECYCLE-CONTRACT:OK`.
2. `nxvm-core-lifecycle-ownership-closure`.
3. Console lifecycle, unified debugger, and FDD DOS-prompt gates.

Stop for owner review if a retained Console/debugger interaction, VM boot
order, provider callback sequence, or FDD DOS prompt changes.
