# M5 T171 S1: Checked RAM Range And Provider Access

## Objective

Make installed RAM range the sole core mapping authority before cold RAM
reconfiguration. No VM session or RAM-capacity command changes occur here.

## Scope

- Split RAM backing allocation capacity from guest-visible installed bytes.
- Reject an access that falls outside the A20-translated installed range; remove
  modulo-size and implicit high-address foldback.
- Convert profile and test callers from raw backing addresses to checked memory
  copy/read/write paths; no provider caches a backing pointer.
- Preserve valid 2 MiB-or-larger default-profile boot addresses and A20 behavior.

## Verification

Add installed-range/A20 boundary probes, run firmware, lifecycle, Console, and
`D:\\fdd.img` DOS-prompt gates, then produce `nxvm_0_5_0171.exe`.

## Stop Conditions

Stop on an invented ROM mapping, a second backing allocation, profile-visible
raw backing pointer, guest address foldback, or FDD boot regression.
