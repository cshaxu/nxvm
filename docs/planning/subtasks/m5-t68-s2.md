# M5 T68 S2: Execution Context Ownership Regression

Status: complete.

## Incident

`build/output/nxvm_0_5_0068.exe` is revoked for full-PC execution. With
`device fdd insert D:\\fdd.img` followed by `start`, it could terminate with
Windows status `0xC0000005`.

## Bisection

The controlled retained-Console probe held standard input open, inserted the
local FDD image, started the machine, and observed the child process for eight
seconds. T65 and T68 P9 were stable; T68 P10 (`47e5593`, PIT output binding)
was the first crashing commit. The PIT layout change exposed, but did not
create, the underlying bug.

## Root Cause and Repair

`vm_composition_control_initialize` bound `control` as the execution-context
callback device. The callbacks cast that pointer to
`vm_composition_live_machine`. Earlier alias-heavy reset paths often read
globals and masked the error. T68's explicit DMA reset dereferenced fields from
the wrongly interpreted control object, causing timing-dependent invalid
writes. The binding now supplies `machine`.

The full-authority smoke asserts that the execution-context device is the live
machine. Full-authority, full-PC session, and FDD/HDD profile gates pass. Six
controlled FDD insert/start trials remained running for five seconds each.

## Rule

Every later explicit-context migration must prove the context object's exact
identity before exercising its callbacks. A fixture-backed retained-Console
FDD `insert -> start` survival probe is required before any future task
artifact is accepted.
