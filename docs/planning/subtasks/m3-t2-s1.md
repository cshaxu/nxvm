# M3 T2 S1: Make Machine Lifecycle Explicit

## Objective

Replace the provisional reset/stop flags with an explicit Machine lifecycle:
initialized, paused, running, stopped, and faulted. Define legal API
transitions, finite run-budget behavior, asynchronous stop observation, and a
stable fault report without introducing a platform thread or guest executor.

## Non-Goals

- Do not execute or decode guest instructions.
- Do not add platform threading, command queues, trace sinks, firmware, DOS,
  product profiles, or CLI behavior.
- Do not modify the provenance-preserved M1 baseline source.
- Do not claim that a zero-execution budget boundary is a full-PC boot run.

## Reference Baseline

- M1 source snapshot: `6d6b7d70ab6ed83ab973d27aeea6db88f4e87e4f`.
- M2 lifecycle and threading contract in
  `docs/history/m0-m4/m2-machine-dos-architecture.md`.
- M3 T1 S2 Machine state ownership and regression boundary.

## Files And ABI Surface

- `src/core/machine.h`, `src/core/machine.c`, `src/core/machine_impl.h`
- `tests/core/machine_lifecycle_smoke.c`
- `tests/core/core_contract_smoke.c`
- `CMakeLists.txt`, `CMakePresets.json`

The public API may expose a lifecycle snapshot and Machine-neutral fault
reporting mechanism for later CPU/device code. It must not expose a mutable
Machine pointer, legacy global state, platform synchronization primitive, or a
host error type. A zero budget is rejected; a finite nonzero budget returns at
a declared boundary.

## Verification

Run:

```text
cmake --preset mingw-gcc-x64
cmake --build --preset m3-machine-lifecycle-gcc
build/mingw-gcc-x64/nxvm-core-machine-lifecycle-smoke.exe
cmake --build --preset m3-machine-instance-gcc
build/mingw-gcc-x64/nxvm-core-machine-instance-smoke.exe
cmake --build --preset m1-baseline-gcc
rg -n "windows.h|win32|Win32|INT 21|ntvdm64 run|products/|nxvm-baseline" src/core tests/core
git diff --check
```

Expected markers:

- lifecycle smoke prints `M3:T2:S1:LIFECYCLE:OK`;
- legal and illegal transitions are deterministic;
- reset reaches the retained `F000:FFF0` checkpoint;
- finite budget, requested stop, and fault each produce one defined reason;
- baseline target builds without a baseline source change.

## Stop Conditions

Stop and escalate if a legal lifecycle transition requires another thread,
direct platform access, a product policy decision, a guest-execution loop, or
a baseline source mutation.
