# M5 T22 S1: Debugger Audit And Migration Design

## Objective

Audit the retained NXVM debugger and approve the later pause-boundary and
unified-backend design without changing runtime code.

## Result

`docs/planning/m5-debugger-migration.md` records actual ownership, target
state semantics, migration order, non-regression limits, and exit evidence.

## Non-Goals

Do not alter Console commands, execution scheduling, debugger behavior, or
create a task artifact. The debugger implementation remains inactive until the
single live-machine authority is complete.

## S2 Authority Correction

The initial audit exposed two independent machine state containers. The
authority correction is recorded in
`docs/planning/m5-machine-authority-migration.md`: the live full-PC state must
migrate into one `nxvm_core_machine` authority without duplicate storage. The
later debugger tasks may not use an adapter to conceal a parallel machine.

## S3 Device-By-Device Execution Plan

Machine convergence precedes debugger work. The approved task sequence is T23
through T43 for the live-machine carrier, then one task per device or firmware
authority, then full-PC closure. The debugger tasks are renumbered to T44 and
T45. See `docs/planning/m5-machine-authority-migration.md`.

## S4 Controlled Migration Method

The authority plan now defines T23 as a no-behavior-change, composition-owned
handle with non-owning references to existing live state. Every later authority
moves through a same-object compatibility path, preserves lifecycle order, and
stops on any duplicate allocation or failed FDD DOS-prompt gate.
