# M5 T1 S1: Implement The Bounded DOS Profile

## Objective

Implement exactly the M5 profile in
`docs/requirements/m5-dos-backend.md` on the verified M3 machine contract and
approved M4 DOS specification.

## Non-Goals

Do not add an unlisted DOS function, dynamic MCB memory, MZ/EXEC, host
filesystem access, Win32 Console/window behavior, or graphics support.

## Entry Conditions

1. M3 has a verified machine contract and snapshot.
2. M4 has approved the DOS ABI specification and test vectors.
3. The M5 profile and its acceptance probes are unchanged or have an
   owner-approved amendment.
4. The DOS-to-machine and DOS-to-fixture-adapter interfaces are documented
   before implementation.

## Expected Surface

- `src/dos/` owns the COM loader, PSP, interrupt dispatcher, fixed-memory
  layout, handle table, fixture filesystem adapter, and deterministic Console.
- `src/machine/` exposes only abstract machine services required by DOS.
- `tests/dos/` owns the four acceptance probes and per-service regression tests.
- `src/dos/` may emit approved DOS-service events to the project-owned optional
  trace sink; no NTVDMx64 header, binary, pipe, or process dependency enters
  the runtime tree.

## Verification

- focused M5 build and test commands defined with the implementation;
- the four acceptance probes in the M5 requirements document;
- a bounded differential comparison only when an experiment record defines it;
- `git diff --check` and updated evidence/tracking records.

## Stop Conditions

Stop for an unlisted service or behavior request. Preserve the evidence, then
route it according to the M5 stop rule rather than widening the implementation.
