# M5 T14 S2: Dependency Migration Map

## Objective

Produce the target-by-target migration sequence and automated source/target
dependency checks required to enforce the M5 DAG and root-composition rule.
Maintain one concise current documentation set: the architecture overview,
module layout, and contracts are the forward authorities; prior plans remain
history only. Freeze the ideal core contracts before mapping any callback
migration.

## Non-Goals

Do not change production ownership, Console/debugger behavior, boot/media
behavior, or execute any T14 S3 through S6 migration.

## Verification

The map names every remaining forbidden edge, its proposed root-composition
binding, affected CMake target, test gate, and stop condition. It also records
the approved `type.*`, `version.*`, `STATUS`, and path-based naming rules. The
current documentation entry points must contain no stale authoritative links.
It freezes the core-machine cooperative execution and root-loop policy before
mapping provider callbacks, including core-only configuration, state, CPU
capability, quantum-result, CPU snapshot, and physical-memory boundaries.

## Stop Condition

Stop for owner approval if resolving an edge would change a retained NXVM user
interaction, lifecycle order, or guest-visible behavior.
