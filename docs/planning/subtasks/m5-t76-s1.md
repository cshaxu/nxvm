# M5 T76 S1: Keyboard Facade Replacement Design

Status: complete.

## Objective

Trace the host keyboard request path from platform input through full-PC
composition and define the smallest replacement for the unbound legacy
`core_machine_keyboard_*` facade.

## Required Outcome

The implementation must target the already session-owned keyboard provider
slot. It must not introduce copied keyboard state, a second keyboard provider,
or a Console/debugger behavior change.

## Verification Plan

After implementation, build `nxvm-0-5-0076` with GCC and run focused keyboard
and retained Console/FDD DOS-prompt gates.

## Design And Result

`nxvm_full_pc` now binds itself as the request-transport consumer context.
When the transport reaches a keyboard-state request at the existing execution
boundary, the consumer calls `core_machine_keyboard_apply_host_state_to()` on
that full PC's already frozen provider slot. No keyboard state is copied and no
global keyboard binding is read or written.
