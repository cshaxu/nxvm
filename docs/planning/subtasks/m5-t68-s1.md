# M5 T68 S1: Core Device Instance Authority

Status: active.

## Objective

Move PIC, PIT, DMA, KBC, VADP, and core RAM A20 port-handler state to explicit
composition-owned device contexts. Each port callback receives its required
device and port reference through a typed registration; it may not select any
mutable state globally.

## Order

1. Replace the port callback table with typed handler/provider entries that
   carry an explicit owner reference while preserving port dispatch order.
2. Migrate RAM A20, KBC, PIC, PIT, DMA, and VADP one device at a time.
3. Preserve IRQ, DMA, display, and POST ordering; add same-object binding and
   two-context isolation checks after each device family.
4. Record VM-only and profile callbacks for T70/T71. T73 deletes forwarding
   aliases only after all callbacks are explicit.

## Stop Conditions

Stop on a copied device state, changed port width/latch semantics, changed
IRQ/DMA order, changed boot/reset/refresh order, Console/debugger regression,
or FDD DOS checkpoint failure.

## P1 Evidence

The port bus now has an explicit typed provider registration with `(t_port *,
owner)` arguments. Provider entries are sparse and owned by the port object,
so only migrated ports allocate storage; the legacy dispatch arrays retain
their original size as a temporary fallback. KBC status port `0x64` is the
first migrated provider and no longer reads `vport`. GCC and the VM port
authority smoke pass.

## P2 Evidence

The RAM A20 handler at port `0x92` now receives explicit RAM and port objects
from the typed provider registry; it no longer reads either selected alias.
GCC plus the RAM and port authority smokes pass. PIC, PIT, DMA, and VADP remain
separate migration slices because their handlers carry IRQ, timer, DMA, or
display ordering responsibilities.

## P3 Evidence

PIC command/data ports `0x20`, `0x21`, `0xa0`, and `0xa1` now bind typed
providers directly to their composition-owned master or slave state. The port
latch is passed to the existing ICW/OCW logic rather than selected globally.
IRQ arbitration, cascading, POST registration, reset, and refresh logic are
unchanged. GCC and the bounded PIC authority smoke pass.

## P4 Evidence

PIT counter and control ports `0x40` through `0x43` now bind typed providers
to the composition-owned timer. Counter read/write and control-word logic take
the provider's port latch and timer state explicitly; retained refresh logic
uses the same timer object without changing tick or output ordering. GCC and
the bounded PIT authority smoke pass.

## P5 Evidence

VADP has no port I/O surface. Its initialize, reset, refresh, and finalization
operations now accept the composition-owned adapter explicitly; retained
wrappers only forward for later T72 orchestration migration. GCC and the VADP
authority smoke pass.

## P6 Evidence

Typed port providers now receive the triggering `port_id` as well as the port
and owner. Existing KBC, RAM, PIC, and PIT providers were adapted and their
focused targets rebuilt. This keeps the provider contract suitable for DMA and
other multi-port devices without introducing per-port wrapper state.

## P7 Evidence

DMA registration now installs typed read/write dispatchers for both 8237
controllers and their page registers. The provider owner is the
composition-owned primary controller, which has non-owning links to the same
secondary controller and latch; no guest state is copied. The former per-port
legacy wrapper span has been deleted rather than left as unreachable code.
GCC, DMA authority, and FDD/HDD full-PC profile gates pass.

## P8 Evidence

DMA initialization, reset, refresh, finalization, and DRQ selection now have
explicit object APIs. VM composition passes its one live machine's latch, DMA
pair, port bus, and RAM objects directly; DMA transfer no longer selects RAM
or latch state through `vram` or `vlatch`. The retained `vdma*` wrappers are
only compatibility callers for the VM FDC endpoint and diagnostic paths,
which move in T70; no new runtime path may use them. The execution-context
callback ABI now receives its bound device object, allowing composition to
invoke machine lifecycle work without a current-session lookup. Focused DMA
and CPU-probe smokes plus the FDD/HDD full-PC profile smoke pass.

## P9 Evidence

PIC initialization, reset, refresh, finalization, and IRQ injection now have
explicit master/slave APIs. VM composition invokes the lifecycle against its
single live PIC pair and port bus. The retained `vpicSetIRQ` entry remains only
for VM FDC and profile-keyboard callers, whose owner-context conversion is
scheduled for T70 and T71; no core lifecycle path selects a PIC globally.
PIC authority and FDD/HDD full-PC profile smokes pass.

## P10 Evidence

PIT output is now an owner-carrying provider slot rather than an unbound
function pointer. Composition binds counter zero directly to its live PIC
master through the core timer-output adapter, so the IRQ0 path does not select
PIT or PIC state globally. PIT reset, refresh, and finalization now take the
live PIT object explicitly; the retained wrappers are diagnostics/compatibility
only. PIT authority and FDD/HDD full-PC profile smokes pass.

## P11 Evidence

KBC now has explicit initialize/reset/refresh/finalize APIs, with its port
registration performed against the live KBC and port objects. VM composition
also invokes the existing explicit VADP lifecycle APIs directly. Neither core
device lifecycle path selects `vkbc` or `vvadp`; remaining VADP use is default
profile firmware work owned by T71. KBC and VADP authority smokes plus the
FDD/HDD full-PC profile smoke pass.
