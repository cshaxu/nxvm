# M5 T12 S9: Canonical Source-Root Migration

## Objective

Execute the approved, source-preserving move order that converges all formal
code under `core`, `vm`, and `vdm`. The imported baseline is a migration
reference, not a final root: move its VM-owned sources by actual owner and
delete it at root closure. Move one source or a tightly coupled
header/implementation pair at a time, repair only its direct include/CMake
edges, and compile before the next move.

## Precondition

M5 T12 S8 closes the machine-directory convergence; no `src/core` forwarding
header or `machine/core/contract` path remains.

## Root Map

Classify every source by actual reuse before moving it. Shared logic goes to
the matching `core/*` owner even when it is a concrete Win32 or Linux
implementation (`core/platform/win32` or `core/platform/linux`); only
product-specific behavior goes to `vm/*` or `vdm/*`.

| Current source | Canonical destination |
| --- | --- |
| `machine/core` | `core/machine` |
| `machine/vm` | `vm/machine` |
| `platform/presentation` | `core/platform` |
| `platform/vm` | `vm/platform` |
| `product/core` | `core/product` |
| `product/vm` | `vm/product`, with `main.c` at `vm/main.c` |
| `products/nxvm` media, Console, debugger, presentation, session | `vm/product` |
| `products/nxvm` profile/default-profile descriptors | `vm/profile/default_profile` |
| `firmware/firmware.*` | `core/machine/firmware.*` |
| `firmware/default_profile.*` and later BIOS/POST/QDX | `vm/profile/default_profile/firmware` |
| `runtime` shared session lifecycle, registry composition, abstract command boundary, generic debug/trace coordination | `core/product/runtime` |
| `runtime` full-machine startup, NXVM Console, VM profile selection, or media policy | `vm/product` |
| `runtime` `ntvdm64 run`, VDM execution-profile selection, display/Console policy, launch parameters, or cancellation policy | `vdm/product` |
| `dos` | `vdm/machine` |
| `adapters` | classify each file into `core`, `vm`, or `vdm`; delete root when empty |
| `app`, `integration` | delete after moving any approved research utility to `tools/research` |

`nxvm-baseline` remains a migration reference while source moves are in
progress. It is not mixed with migrated code; it is deleted after its
VM-owned sources have moved and the formal product no longer builds from it.

## CMake Cutover Rule

Each source slice first changes only its CMake source-set path and direct
includes. Static target names may retain their existing names until the slice
is verified, but `nxvm.exe` must ultimately compile from `vm/main.c`, and the
future `ntvdm64.exe` from `vdm/main.c`. A formal executable may not compile
from a migration-source root after that root's slice closes. At S9 closure,
only `core`, `vm`, and `vdm` may be top-level `src` roots.

## Non-Goals

Do not alter source logic, switch a platform producer, alter keyboard mapping,
Console/window behavior, display modes, thread lifetime, debugger behavior, or
the `nxvm.exe` identity. Do not bulk-move a directory before its individual
file moves have compiled. Stop for an owner decision rather than guessing a
destination for any file whose actual dependencies do not establish ownership.

## Verification

For each move, prove `git mv` provenance, direct-include repair, and the
affected GCC target. At root closure, prove no formal CMake target compiles a
source from the removed root; build `nxvm.exe` from `vm/main.c`; run the finite
CPU, FDD/HDD reset-vector, Console, and debugger gates. No raw instruction
recorder run is allowed.

## Stop Condition

Stop before any source move that changes a user-visible behavior. The deferred
keyboard-state producer switch remains M5 T12 S10.
