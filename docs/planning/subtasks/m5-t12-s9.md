# M5 T12 S9: Canonical Source-Root Migration Design

## Objective

Define the bounded, source-preserving move order that converges all formal code
under `core`, `vm`, and `vdm`, leaving only `adapter` and `nxvm-baseline` as
non-product roots. The plan maps every current root to its final owner, CMake
target, entry point, and regression gate before any root-level move begins.

## Precondition

M5 T12 S8 closes the machine-directory convergence; no `src/core` forwarding
header or `machine/core/contract` path remains.

## Root Map

| Current source | Canonical destination |
| --- | --- |
| `machine/core` | `core/machine` |
| `machine/vm` | `vm/machine` |
| `platform/presentation` | `core/platform` |
| `platform/vm` | `vm/platform` |
| `product/core` | `core/product` |
| `product/vm` | `vm/product`, with `main.c` at `vm/main.c` |
| `products/nxvm` media, Console, debugger, presentation, session | `vm/product` |
| `products/nxvm` profile/default-profile descriptors | `vm/profile/default_profile` |
| `firmware/firmware.*` | `core/machine/firmware.*` |
| `firmware/default_profile.*` and later BIOS/POST/QDX | `vm/profile/default_profile/firmware` |
| `runtime` shared registry/session primitives | `core/product` |
| `runtime` VM/VDM profile and composition policy | split into `vm/*` and `vdm/*` by owner |
| `dos` | `vdm/machine` |
| `adapters` | `adapter` |
| `app`, `integration` | delete after moving any approved research utility to `tools/research` |

`nxvm-baseline` remains an independently buildable reference. It is not moved
and cannot gain new product behavior.

## CMake Cutover Rule

Each source slice first changes only its CMake source-set path and direct
includes. Static target names may retain their existing names until the slice
is verified, but `nxvm.exe` must ultimately compile from `vm/main.c`, and the
future `ntvdm64.exe` from `vdm/main.c`. A formal executable may not compile
from a migration-source root after that root's slice closes.

## Non-Goals

Do not move runtime source, switch a platform producer, alter keyboard mapping,
Console/window behavior, display modes, thread lifetime, debugger behavior, or
the `nxvm.exe` identity. This subtask changes governance only.

## Verification

The design records: `vm/main.c` and `vdm/main.c` entry rules; root-removal
order; exact ownership of the existing `firmware`, `runtime`, `product`, and
`products` sources; adapter/baseline exit criteria; per-slice compile and
regression gates; and the explicit rule that moves happen in small batches with
immediate include/CMake repair. Review every forward-looking governance
document for conflicting paths. No raw instruction recorder run is allowed.

## Stop Condition

Stop before any source move that changes a user-visible behavior. The deferred
keyboard-state producer switch becomes M5 T12 S10.
