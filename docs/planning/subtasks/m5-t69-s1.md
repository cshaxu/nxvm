# M5 T69 S1: Session-Owned Service Registries

Status: active.

## Objective

Replace process-static provider storage for the retained block, keyboard,
display, trace, and firmware service surfaces with one composition-owned
registry. A provider receives its owning session context directly; no provider
callback may discover a selected machine through a global.

## Ownership Map

| Service | Current static binding | Owner after T69 | Remaining consumer migration |
| --- | --- | --- | --- |
| Block | `core_machine_block_*` | live-machine service registry | default BIOS/disk firmware in T71 |
| Keyboard | `core_machine_keyboard_*` | live-machine service registry | default keyboard firmware in T71 |
| Display | `core_machine_display_*` | live-machine service registry | CGA firmware and presentation orchestration in T71/T72 |
| Trace | no selected global; state is already `core_machine` owned | retain explicit machine state | T72 debugger/product attachment |
| Firmware | session-model descriptor registry is already owned/frozen | retain session-model state | default BIOS/QDX execution binding in T71 |

## Ordered Parts

1. Define the live-machine service-registry storage and its initialize, bind,
   freeze, unbind, and finalize order. It references existing providers and
   never mirrors media, display, or keyboard guest state.
2. Convert block, keyboard, and display interfaces to explicit registry
   operations; migrate composition callers that already receive a live-machine
   pointer.
3. Add same-object and two-registry isolation gates. Record firmware callers
   that cannot change before T71 gives them an explicit profile/session
   context.
4. Remove all process-static provider slots. Compatibility facades may remain
   only if they forward through an explicit caller-owned registry; a
   current-registry selector is prohibited.

## Invariants

- Core stays independent of VM, VDM, host platform, and profile headers.
- The registry is configured before machine reset/POST, frozen before guest
  execution, and unbound/finalized after the existing machine teardown order.
- No copy of block media, keyboard queue, display snapshot, trace buffer, or
  firmware descriptor state is permitted.
- Console grammar, display behavior, keyboard mapping, boot/reset order, and
  media semantics remain unchanged.

## Stop Conditions

Stop on any provider that needs a second state copy, a selected registry
global, a core-to-VM dependency, changed guest-visible ordering, or a
Console/FDD profile regression.
