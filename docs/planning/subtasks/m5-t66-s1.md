# M5 T66 S1: CPU And Executor Instance Authority

Status: active.

## Objective

Replace retained CPU/executor selected-session state with one explicit CPU
context owned by `vm_composition_live_machine` and passed through decode,
instruction helpers, the execution loop, probes, and debugger adapters.

## Scope

- Map every `vcpu`, `vcpuins`, CPU `*_current`, `*_bind_live`, and
  `*_unbind_live` declaration and use.
- Define the explicit CPU/executor context and its lifecycle before moving a
  caller.
- Migrate read/write/reset/refresh/decode/exception and CPU debug paths without
  changing instruction, BIOS, port-I/O, or Console behavior.
- Make CPU aliases deletion-ready; T73 deletes the shared legacy selection
  layer after device and profile callers have migrated.

## Ordered Parts

1. P1 establishes `core_machine_cpu_execution_context` as a child of the VM
   live machine. It references exactly the existing CPU and decoder storage
   and owns CPU stop/reset requests.
2. P2 changes the CPU instruction table and every internal executor helper to
   receive that context explicitly. The function-pointer ABI is typed; no
   thread-local or selected-session substitute is allowed.
3. P3 converts composition, probe, debug, and the instruction-handler ABI.
   Device and profile callbacks receive their explicit CPU context in their
   owning T68--T71 migrations.
4. P4 adds a two-context isolation smoke and records the remaining
   device/profile callers. T73 performs the one global legacy-alias deletion
   only after every caller is explicit.

Parts are recovery boundaries only. T66 produces one artifact,
`nxvm_0_5_0066.exe`, after P4 and all gates pass.

## P2 Evidence

P2 is complete. `cpu_instructions.c` passes the composition-owned execution
context through its internal helpers and typed instruction table. Its retained
`vcpuins*` surface is now a compatibility adapter over the context; it no
longer supplies the executor's working state. The default-profile QDX opcode
handler accepts the same typed context. Full GCC/Ninja build, the CPU probe's
expected `#UD`, and the FDD/HDD full-PC profile smoke passed on the recorded
local fixtures. P3 remains active.

## Current Map

- `core/machine/cpu.c`: 90 `vcpu` and 18 `vcpuins` uses plus CPU stop/reset
  flags currently hidden as file statics.
- `core/machine/cpu_instructions.c`: 1,324 `vcpu` and 2,428 `vcpuins` uses;
  its local instruction functions must share one explicit context rather than
  individually selecting a global object.
- VM/profile consumers: composition refresh/probe/full-PC/debug, VM debugger,
  CMOS, and default-profile QDX/CGA/disk/keyboard firmware.
- `core/product/runtime/execution_context` already carries the VM CPU pointer,
  but its process-global current selector is T72 scope and cannot become the
  replacement CPU accessor in T66.

## Non-goals

- RAM, port, device, firmware, registry, and product alias migration.
- Multi-session UI, new Console grammar, CPU feature expansion, or DOS work.

## Gates

- GCC full build; CPU probe including expected `#UD`; CPU authority and stop
  smokes; retained Console/debugger; FDD/HDD profile/session; bounded FDD
  `INT 21h`; dependency-DAG; and `nxvm_0_5_0066.exe`.

## Stop Conditions

Stop if context passing requires duplicated CPU/decoder state, changes guest
instruction ordering or reset behavior, changes Console/debugger UX, or fails
the fixture-backed FDD DOS checkpoint.
