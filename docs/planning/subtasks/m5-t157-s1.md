# M5 T157 S1: Session CPU And FPU Profile UX

## Objective

Expose frozen CPU and FPU profiles through NXVM Console session creation
without giving core/product knowledge of VM-specific model enums.

## Scope

- Accept `SESSION OPEN --cpu <8086|80186|80286|80386> --fpu
  <none|8087|80287|80387>`.
- Keep omitted values at `80386+none`; session 0 follows the same default.
- `SESSION LIST` shows each session's frozen CPU and FPU selection.
- Reject malformed values and all present-FPU choices clearly until their
  implementation exists. Profiles do not hot-switch after session creation.
- Preserve Console, debugger, boot, FDD, and window/Console lease behavior.

## Boundary

`core/product/session` carries opaque creation arguments and copied generic
snapshot text only. `vm/product` owns Console grammar and presentation;
`vm/composition/session` parses VM profile choices, creates the frozen
`core_machine_config`, and owns rejection of unavailable present FPU models.

## Exit

Dedicated Console/session probes prove default selection, all accepted CPU
profiles with `FPU=none`, rejected present FPU selection, immutable profiles,
and the existing DOS boot and debugger gates. Produce
`build/output/nxvm_0_5_0157.exe`.
