# M5 T170 S1: Cold-Start Lifecycle Implementation

## Objective

Implement the T169 lifecycle contract: reset and observed stop end in a
cold-start-ready `STOPPED`; `PAUSED` remains an execution/debug boundary.

## Scope

- Make `core_machine_reset` finish in `STOPPED`.
- Permit `core_machine_run` from `STOPPED` and `PAUSED`.
- Make a stop request reset core state and frozen providers before publishing
  `STOPPED`; preserve the stop run result.
- Permit paused-boundary memory, port, and A20 helpers at `STOPPED`, because
  it is a stable pre-start inspection/injection boundary.
- Keep a guest reset request as one core cold reset; VM clears only its
  VM-private debug state after that returned result.
- Add a focused lifecycle smoke; update retained lifecycle/trace expectations.

## Non-Goals

No RAM allocation/map change, provider pointer cleanup, `DEVICE RAM` routing,
CPU/FPU/profile hot switch, UI grammar change, platform-handle change, or VDM
runtime feature.

## Files And Contracts

- `src/core/machine/machine.c`, `memory_interface.c`, and `port_interface.c`
- `src/vm/composition/session/runner.c`
- lifecycle and trace smoke sources plus CMake artifact/preset registration

## Verification

Build GCC targets for the focused lifecycle/trace/core contract smokes, the
retained Console lifecycle and session-manager gates, and `nxvm-0-5-0170`.
Run the focused executables and copy
`build/output/nxvm_0_5_0170.exe`. Preserve the FDD DOS-prompt gate before

## Stop Conditions

Stop for review on Console/debugger grammar changes, a second run path,
`STOPPED` without a valid reset vector/provider reset, a running-state mutation
through public helpers, or a boot regression.
