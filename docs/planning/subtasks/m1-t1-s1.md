# M1 T1 S1: Design The GCC Migration

## Objective

Define the bounded GCC migration before source import or behavior changes. The
design identifies the exact active NXVM revision to assess, compiler and build
graph changes, portability shims, warning policy, expected patch classes and
their budgets, baseline test plan, rollback point, and stop conditions. Its
approved result is the required entry gate for M1 T2 S1.

## Non-Goals

Do not import NXVM source, alter the sibling checkout, implement an owned DOS
backend, add a Console `load` command, host-drive mapping, product CLI, new
graphics/device behavior, or Microsoft component research code. Do not claim
redistribution rights for, or commit, local image fixtures.

## Entry Conditions

1. Confirm the M0 GCC smoke record and default toolchain contract apply to the
   active ntvdm64 checkout.
2. Inspect the current sibling NXVM `HEAD` without modifying it.
3. Verify the local fixture identities in `docs/fixtures/m1-local-images.md`;
   keep them read-only and outside the repository.

## Expected Surface

- a versioned migration design with source-revision assessment, target/build
  graph, C11 portability inventory, compatibility-header boundary, warnings,
  patch budget, test commands/markers, rollback point, and stop conditions;
- explicit classification of each anticipated change as build-only,
  compatibility-only, behavior-affecting, or deferred;
- a T2 import/provenance, FDD/HDD experiment, and optional trace plan; and
- an owner-approved Go/No-go decision for M1 T2 S1.

## Verification

- review confirms all expected compiler failures and warnings are either within
  a bounded patch class or named as a stop condition;
- test plan contains the exact GCC configuration/build commands and baseline
  FDD/HDD scenarios to execute after import; and
- `git diff --check`, tracking, and compact verification evidence are updated.

## Stop Conditions

Stop and request direction if the migration needs an unbounded compiler
workaround, changes NXVM behavior before a baseline exists, requires modifying
the sibling checkout, the fixtures do not match their recorded hashes, their
legal status prevents local use, or required source/license notices are missing.
