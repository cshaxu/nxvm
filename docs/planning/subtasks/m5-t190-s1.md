# M5 T190 S1: Module-Owned Internal Symbols

## Objective

Remove `NXVM` and `NTVDM64` product prefixes from internal C identifiers,
header guards, CMake targets, and test helper identifiers. Use the owning
source path: `type_*`/`TYPE_*`, `core_*`/`CORE_*`, `vm_*`/`VM_*`, and
`vdm_*`/`VDM_*`.

## Non-goals

- Do not change user-visible NXVM Console text, window class, executable name,
  artifact filename, or historical documentation.
- Do not change behavior, module ownership, public command grammar, or source
  file layout.

## Mapping

- `ntvdm64_type_*` and `NTVDM64_TYPE_*` become `type_*` and `TYPE_*`.
- `ntvdm64_status` and `NTVDM64_STATUS_*` become `type_status` and
  `TYPE_STATUS_*`.
- Core machine/product identifiers become `core_machine_*`,
  `CORE_MACHINE_*`, `core_product_*`, or `CORE_PRODUCT_*`.
- VM and VDM identifiers become `vm_*`/`VM_*` and `vdm_*`/`VDM_*`.
- Internal CMake libraries/tests follow the same owners; the product artifact
  target may retain `nxvm-0-5-0190` solely because it produces `nxvm.exe`.

## Applicable Rules And Evidence

- `RULES.md` ownership, interface/provider, and file-name rules apply.
- Reject any remaining `NXVM`/`NTVDM64` identifier token in active source,
  tests, or CMake, except approved user-visible product identity literals and
  artifact names.
- Configure and build the current GCC artifact and focused Console, session,
  machine, and VDM-minimal gates.

## Stop Conditions

Stop if a rename changes retained Console output, window behavior, artifact
identity, or creates an unresolved ownership mapping.
