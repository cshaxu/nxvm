# M5 T71 S1: Profile Firmware Authority

Status: active.

## Objective

Move default-profile BIOS/QDX/CGA/keyboard/disk firmware consumers from the
selected live-machine facade to explicit composition-owned profile objects and
provider slots. Preserve POST, interrupt-registration order, boot/reset,
retained Console, and FDD DOS prompt behavior.

## Non-goals

No new firmware feature, ROM format, profile selection UX, Console grammar,
or DOS backend behavior is introduced.

## Required Evidence

- Map every `vbios`, QDX table/current accessor, and default-profile static
consumer before deletion.
- Each firmware callback receives its owner or a non-owning profile context.
- Default-profile, full-authority, Console, and fixture FDD start gates pass.
- The T71 artifact uses `0.5.0071` only after the source scan is clean.

## Ownership Map

| Unit | Owned state | Required non-owning links | Migration order |
| --- | --- | --- | --- |
| BIOS | `t_bios` | RAM, block-provider slot | 1 |
| QDX | `t_qdx` table | CPU execution context | 2 |
| disk firmware | no private mutable state | QDX table, CPU execution, RAM, block-provider slot | 3 |
| keyboard firmware | private key queue/state | QDX table, CPU execution, KBC, port | 4 |
| CGA firmware | private video-mode/cursor state | QDX table, CPU execution, RAM, VADP | 5 |

The profile context is non-owning: its links must point at the composition's
existing CPU/execution/RAM/device/provider objects. It may not cache copied
register, RAM, media, or display state. QDX dispatch receives that context via
the CPU instruction handler registration, so an interrupt handler never finds a
session through a selected-object global.

## Ordered Parts

1. Add the default-profile context and move BIOS lifecycle/registration to
   explicit BIOS and RAM/provider arguments.
2. Move QDX lifecycle/table/dispatch to the profile context and bind it to the
   composition CPU execution object.
3. Move disk, keyboard, and CGA handler registration and direct state access
   through the same context; preserve their registration order.
4. Move Console/full-PC/smoke callers, delete BIOS/QDX selected-object APIs,
   then build the T71 artifact and run the required gates.

## Stop Conditions

Stop if migrating an interrupt handler changes registration order, requires a
second machine state, changes retained Console behavior, or fails the FDD
insert/start survival gate.

## P1 Evidence

BIOS selected-object storage and its current/bind/unbind APIs are deleted.
Composition now holds and passes its `t_bios` object explicitly for
initialization, POST and interrupt registration, reset, refresh, finalization,
Console inspection, and boot-device selection. BIOS reset receives the
composition RAM and frozen block-provider slot explicitly. The focused BIOS
authority smoke passes. RAM access inside profile firmware remains assigned to
the shared profile-context conversion in P2--P3; P1 adds no copied state or
guest-visible lifecycle change.

## P2 Evidence

`t_qdx` is now reached through the composition-owned default-profile context.
The core CPU execution context carries only an opaque non-owning extension;
core code has no VM-profile dependency. The QDX opcode handler obtains that
context from its typed execution argument, so it dispatches the real QDX table
without a selected current-object accessor. Initial keyboard, CGA, and disk
registrations receive the explicit table. Focused QDX and disk-firmware gates,
full-PC closure, and the three-second DOS-prompt gate pass. The handlers'
remaining direct RAM/CPU/video aliases are P3 work; no new selected QDX state
remains.

## P3 Evidence

QDX now stores typed profile handlers rather than untyped no-argument addresses.
The INT 13 disk handlers receive the profile context and use its execution
CPU, RAM, and frozen block-provider slot directly. The new core memory helper
only returns an address within a supplied RAM object; it does not select a
session. Disk-firmware and three-second DOS-prompt gates pass. Keyboard and
CGA handlers still use the typed ABI's temporary adapters while their direct
RAM/CPU/VADP references move in the next part.

## P4 Evidence

INT 13 disk handlers now use the default-profile context's execution CPU, RAM,
and frozen block-provider slot. They neither select a live session nor retain a
copy of machine state. The disk-firmware, full-authority, and three-second DOS
prompt gates pass.

## P5 Evidence

Keyboard firmware now receives the same profile context through both its QDX
handlers and frozen keyboard-provider slot. BIOS keyboard flags and the key
ring buffer are read and written through the composition RAM; IRQ and port
operations use the explicit execution context. The keyboard-firmware,
full-authority, and three-second DOS-prompt gates pass. CGA remains the final
firmware consumer to migrate.
