# M5 T24 S1: CPU And Executor Authority Migration

## Objective

Move the retained full-PC CPU and instruction-executor implementation into the
canonical `core/machine/cpu.*` and `cpu_instructions.*` units. The one VM live
machine carrier becomes the sole storage owner for the full-PC CPU and decoder
objects. No duplicate CPU state, reset path, or execution loop is introduced.

## Reference Baseline

`c722dcb` retains the original NXVM Console/debugger, FDD/HDD behavior, and
the T23 non-owning live-machine carrier.

## Source Map

| Current unit | Target | Required action |
| --- | --- | --- |
| `core/machine/vcpu.c/.h` | `core/machine/cpu.c/.h` | Move the retained CPU state, lifecycle, control requests, and existing direct-call compatibility surface. Merge the small M3 CPU-state API into this public unit. |
| `core/machine/vcpuins.c/.h` | `core/machine/cpu_instructions.c/.h` | Rename the retained decoder/executor without changing opcode behavior. |
| Existing `core/machine/cpu.c/.h` | `machine.c` and merged `cpu.h` | Keep the minimal core-machine test API, but move its implementation beside the other machine lifecycle implementation so the retained CPU source compiles only in `nxvm-core-machine`. |
| `vm/composition_live_machine.*` | same | Embed the sole `t_cpu` and `t_cpuins` storage, bind the core CPU accessors to those exact objects, and clear the binding at existing finalization. |
| VM composition, VM machine, default-profile firmware, and tests | same | Switch include paths to the canonical names. Legacy `vcpu`/`vcpuins` spellings may remain only as direct current-object accessors until each dependent authority is migrated. |

## Forbidden Dependencies And Non-Goals

- `core/machine` must not include `vm/*`, profiles, platform, Console, or
  debugger code.
- Do not alter opcode semantics, CPU capability claims, boot order,
  `vmachineInit/Reset/Refresh`, Console grammar, debugger grammar, or media
  behavior.
- Do not move RAM, ports, PIC, or any later authority; those are T25 onward.
- Do not construct the minimal `nxvm_core_machine` for a full-PC session.

## Required Order

1. Move the small M3 CPU implementation out of `cpu.c`, then `git mv` the
   retained `vcpu.c/.h` to `cpu.c/.h`; repair direct includes and CMake before
   continuing.
2. `git mv` `vcpuins.c/.h` to `cpu_instructions.c/.h`; repair direct includes
   and CMake before continuing.
3. Embed the actual CPU/decoder storage in the live carrier and bind only
   direct aliases/accessors to it. Preserve existing lifecycle call order.
4. Run focused identity, CPU-stop, full-PC FDD/HDD, Console/debugger, GCC, and
   dependency-DAG gates. Build and copy `build/output/nxvm-m5_t24.exe`.

Expected focused markers are `M5:T24:S1:CPU-AUTHORITY:OK`,
`M5:T14:S3:CPU-STOP:OK`, and `M3:T3:S1:FULL-PC-PROFILE:OK`. The Console check
must retain `HELP`, `DEBUG`, and `EXIT` behavior.

## Stop Conditions

Stop immediately if the move needs a second CPU/decoder allocation, changes
the retained initialization/reset/refresh order, creates a core-to-VM
dependency, changes Console/debugger behavior, or fails the FDD DOS-prompt
checkpoint.

## Result

Complete. `vcpu.c/.h` now lives as `cpu.c/.h`, and `vcpuins.c/.h` now lives as
`cpu_instructions.c/.h`. The former minimal CPU-state implementation was
merged into the canonical CPU interface and `machine.c`; no temporary source
unit remains. The live-machine carrier embeds the sole full-PC CPU and decoder
storage. Legacy `vcpu` and `vcpuins` spellings are temporary direct accessors
to those exact embedded objects, not globals, copies, or caches.
