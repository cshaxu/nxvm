# M5 T25 S1: RAM/A20 Authority Map

## Objective

Map the retained full-PC RAM/A20 storage, allocation, translation, direct
read/write, lifecycle, and callback surface before changing RAM authority.

## Reference Baseline

M5 T24 closes with the sole full-PC CPU/decoder instance embedded in
`vm_composition_live_machine`; RAM remains inherited `vram` storage.

## Non-Goals

Do not move RAM storage, change A20 behavior, alter CPU/port/device ownership,
or create a T25 executable during this mapping subtask.

## Required Record

Identify every `vram` definition and direct caller, its initialization/reset/
refresh/finalization order, all real/physical/linear address interfaces, A20
state, and each CPU, firmware, device, debugger, platform, and test callback.
The next implementation subtask may begin only after the map names a direct
same-object migration and the focused FDD DOS-prompt gate.

## Stop Conditions

Stop for design review if the map needs copied RAM, a second allocation,
changed translation semantics, reordered lifecycle, a core-to-VM dependency,
or a weakened FDD DOS-prompt regression.
