# M5 T25 S1: RAM/A20 Authority Map

## Objective

Map the retained full-PC RAM/A20 storage, allocation, translation, direct
read/write, lifecycle, and callback surface before changing RAM authority.

## Reference Baseline

M5 T24 closes with the sole full-PC CPU/decoder instance embedded in
`vm_composition_live_machine`; RAM remains inherited `vram` storage.

## Non-Goals

Do not move RAM storage, change A20 behavior, alter CPU/port/device ownership,
or create a T25 executable during this mapping subtask.

## Authority Map

`core/machine/vram.c` owns the current full-PC RAM object: the sole `t_ram
vram` global, its 16 MiB allocation, physical and real-address translation,
A20 flag, port `0x92` callbacks, and a PIT channel-1 registration. Its backing
buffer is the only RAM used by retained CPU execution, DMA, firmware, debugger
memory callbacks, and full-PC boot.

The small `nxvm_core_machine.memory` buffer in `memory.c` is a separate M3
minimal-model test/session implementation. It is not constructed by NXVM
composition and is not an alternative full-PC RAM authority. T25 preserves its
independent tests while moving the retained implementation into the canonical
memory unit; it must not join that buffer to a bootable session.

| Surface | Current caller or behavior | T25 constraint |
| --- | --- | --- |
| Storage | `vram.connect.pBase`, `size`, and `flagA20` | Embed the sole `t_ram` in `vm_composition_live_machine`; no second allocation. |
| Allocation | `vramInit` zeroes the object then allocates 16 MiB; `core_machine_memory_allocate` may reallocate it | Preserve pointer and allocation behavior, including the existing caller-controlled resize path. |
| Real address | `vramGetRealAddr` wraps A20 then takes modulo RAM size | Preserve its pointer-returning semantics for BIOS, keyboard, video, disk, tests, and debugger paths. |
| Physical access | CPU and DMA use `vramReadPhysical`/`vramWritePhysical`; reads mirror high ROM addresses at `0xfffe0000` through `0xffffffff` with `& 0x001fffff` | Preserve the asymmetric historical read/write behavior exactly. |
| A20 | Port `0x92` callbacks read/write bit `0x02` through `vport.data.ioByte`; reset disables A20 | Keep callbacks registered through the existing port object. Port storage and dispatcher remain T26 work. |
| Firmware | `vbios`, `qdcga`, `qdkeyb`, and `qddisk` directly use real-address macros | Retain direct same-object access until their later owner-local conversions. |
| Lifecycle | `vmachineInit`: `vportInit`, device setup, `vpitInit`, `vpicInit`, then `vramInit`; reset calls `vportReset`, `vvadpReset`, `vramReset`, `vbiosReset`; refresh calls `vramRefresh` between VADP and CMOS; final calls `vramFinal` last | Do not reorder any call, callback registration, or free. |

The live carrier currently has a non-owning `ram` reference. T25 will replace
that reference with its one embedded `t_ram` object, bind a core memory-current
accessor to it, and retain temporary `vram` compatibility only as a direct
alias. CPU, DMA, firmware, Console, debugger, and tests will therefore still
address the same bytes. No caller may cache, copy, or synchronize RAM state.

## Direct Consumer Groups

- `cpu_instructions.c`: physical instruction, page-table, and operand access.
- `vdma.c`: channel transfers and memory-to-memory DMA.
- VM composition: lifecycle, RAM-size reporting, CPU probe, control-only
  binding, and full-PC configuration resize.
- Default-profile firmware: BIOS data/ROM/IVT setup, keyboard buffer, text
  state, and INT 13h buffers.
- Debug and tests: real-memory callbacks, reset-vector injection, live-object
  identity, and the independent minimal-machine memory API tests.

## Result

Complete. The map identifies a same-object migration with no new guest-memory
allocation. The actual source move, accessor binding, and focused authority
smoke are bounded by `m5-t25-s2.md`.

## Stop Conditions

Stop for design review if the map needs copied RAM, a second allocation,
changed translation semantics, reordered lifecycle, a core-to-VM dependency,
or a weakened FDD DOS-prompt regression.
