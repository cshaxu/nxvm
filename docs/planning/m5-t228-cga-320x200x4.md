# M5 T228: CGA 320x200x4 Graphics

## Original Request

Implement bounded CGA `320x200x4` graphics in VADP: video memory layout,
scanlines, `3D8h`/`3D9h`, palette/mode state, raster state, and a copied pixel
snapshot. Do not admit EGA or VGA. The product display policy is `console`,
`window`, or `auto`: Console is text-only; Window presents text and graphics;
Auto begins in Console and permanently moves to Window at the first supported
graphics-mode transition.

### VADP Contract

- VADP remains the sole owner of `3D4h`, `3D5h`, `3D8h`, `3D9h`, `3DAh`, the
  `B8000h` 16 KiB CGA window, raster phase, dirty generation, and copied
  snapshots. Neither QDCGA, composition, nor a renderer owns a second mode,
  palette, or VRAM state.
- Text mode retains the current text snapshot and T220 raster semantics.
  Graphics mode is selected only when `3D8h` has bit 1 set and bit 4 clear.
  Mode 5 has identical memory geometry but is not separately claimed. Mode
  6/640x200, composite artifact color, EGA, VGA, and VBE remain unsupported.
  T228 does not add a private BIOS handler: normal ROM `INT 10h` code may use
  VADP through ordinary port writes, and direct port programs have identical
  controller state.
- In graphics mode the window is `B8000h..BBFFFh`. A pixel `(x, y)`, with
  `0 <= x < 320` and `0 <= y < 200`, reads byte
  `(y & 1) * 0x2000 + (y >> 1) * 80 + (x >> 2)`. Its 2-bit index occupies
  `6 - 2 * (x & 3)` in that byte. The index selects background for zero and
  one of the three current foreground palette entries otherwise.
- `3D9h` contributes the RGBI background from bits 0--3 and the palette family
  from bit 5. Bit 4 remains an alpha-mode control and does not invent a
  graphics-intensity variant. The S1 probe fixes the two admitted foreground
  triples and rejects unsupported mode/control
  combinations rather than silently presenting them as CGA graphics.
- The existing elapsed-tick raster owner remains VADP. `3DAh` is an
  observation only; host time and repeated port reads never advance it.

### Snapshot And Presentation Contract

- `core_machine_display_snapshot` becomes a tagged copied snapshot: text data
  or a 320x200 indexed-pixel payload plus resolved RGBI palette. It never
  exposes a guest-memory pointer.
- `core_platform_display_frame` is likewise tagged and copied. VM composition
  translates snapshot to frame; platform renderers consume frame data only.
- `console` keeps the retained text renderer. A supported graphics transition
  reports a defined presentation limitation and requests the same composition
  stop/result boundary; it must not discard or synthesize guest pixels.
- `window` starts and retains the Win32 window renderer for both kinds.
  `auto` starts with the Console text path, switches once at the first admitted
  graphics frame, and keeps the same session in Window mode thereafter.
  Linux Window behavior is a static completeness follow-up only; no WSL or
  Linux runtime validation is introduced by T228.

### Rules, Risks, And Stop Conditions

Applicable rules: one VADP owner; core has no VM/platform dependency;
composition is the only core-to-platform bridge; platform does not mutate guest
state; no host-clock guest timing; no global/current-object facade; no
unapproved retained Console/debugger/startup/boot regression. This is a new
capability, so the defect similar-issue sweep is not applicable. The S1 design
sweep is `rg -n "Graphics selection is deliberately inert|display_snapshot|display_frame|configure_text_video|qdcga" src tests CMakeLists.txt` and
its listed paths are the complete current graphics seam.

Stop before S2 if implementation requires a second VADP state, renderer VRAM
access, a VM-side scheduler, an unbounded graphics family, a host-clock
shortcut, or a product-visible display behavior beyond this approved policy.

## S2: Owned Implementation

**Status:** Complete.

- `core/machine/vadp` remains the only CGA state owner. It interprets the
  admitted `3D8h`/`3D9h` subset and copies either text or indexed pixels from
  its single B8000h window into a tagged display snapshot.
- VM composition copies that snapshot into a tagged platform frame. The Win32
  window renderer consumes the copied indexed frame; Console and Linux Console
  consume text only and never borrow guest VRAM.
- `DEVICE display console|window|auto` is a product selection. The product
  provider has its own three-value enum; only its composition adapter maps it
  to the platform run-context, preserving the product/platform dependency
  boundary.
- In explicit Console mode a supported graphics transition ends the current
  runner boundary and prints a clear selection requirement. `auto` records one
  promotion at that same boundary, then resumes the same `vm_session` and
  `core_machine` in Window mode. No second machine, executor, or graphics
  state is created.
