# M5 T148: Deterministic Session Close

## Outcome

`core_product_session_manager_close()` is the sole product-visible close path.
It rejects a table with one live item before calling the composition provider,
so a product cannot reach a no-session/no-selection state. For a valid close it
calls the injected synchronous provider destruction path, removes the opaque
entry, and selects the lowest remaining ID when the selected entry closed.

VM provider close invokes `vm_session_destroy()`, whose existing lifecycle
requests stop, joins an active platform run handle, finalizes providers, and
then releases the concrete session. The Console grammar now accepts
`SESSION CLOSE [id]`; no-ID means the selected session. Product exit scans all
copied snapshots and refuses while any session is running or paused.

## Rules Exit Check

Core owns generic table/selection policy; VM composition remains the concrete
session owner. Close has no global/TLS selector, creates no second execution
path, and cannot expose an empty manager state.
