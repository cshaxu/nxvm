# M5 T164: Core Configuration And Observation Boundary

## Result

Generic mutable executor/shared-device access is now explicitly limited to
`INITIALIZED` composition binding through `core_machine_configuration_*_borrow`.
The historical `core_machine_executor_*_borrow` surface has no active caller.
The retained composition debugger uses `core_machine_debug_*_borrow`, which
requires a returned machine boundary. CPU state, first-fault data, and
lifecycle can be copied together through `core_machine_capture_observation()`.

`vm_session_config.memory_bytes` now reaches `core_machine_config` at creation;
tests no longer resize frozen RAM directly. This is configuration plumbing, not
the `DEVICE ram` behavior change deferred to T165.

## Rules Review

- Core owns all CPU/RAM/port/shared-device storage and lifecycle; composition
  receives only purpose-named binding references.
- Product commands do not receive mutable core child objects.
- Debug adaptation is explicit-session and return-boundary-only; it has no
  global/current-object selection.
- No NXVM Console command grammar, startup flow, or boot device behavior was
  changed.
