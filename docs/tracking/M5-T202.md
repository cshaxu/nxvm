# M5 T202: Keyboard Transport Surface Closure

Status: complete.

## Objective

Remove the unused VM platform modifier-query façade. Keyboard transport keeps
only the real platform-to-session guest keypress route; core keyboard provider
modifier observation remains unchanged for firmware and core callers.

## Scope

- Delete `vm_platform_keyboard_modifier`, the sink `get_modifier` callback,
  `vm_platform_keyboard_get_modifier_for()`, and the session forwarding switch.
- Simplify the platform input smoke to prove only keypress transport behavior.
- Add a static closure gate and advance the current artifact to `0.5.0202`.

## Non-Goals

- Do not change core keyboard provider APIs, QDKEYB modifier behavior,
  keyboard-state ingress, KBC, F9 cancellation, scan-code mapping, or Linux
  native verification status.

## Rules And Stop Conditions

- Keep only abstractions with a real producer/consumer path.
- Preserve the retained keypress ingress, Console/debugger, two-session, and
  FDD DOS-prompt behavior.
- Stop for a new platform-to-core dependency, input-order regression, or a
  retained behavior failure.

## Required Evidence

- Source gate rejects the deleted VM modifier façade and session forwarding.
- Platform keypress smoke, current CTest/static gates, and a `0.5.0202`
  Console `EXIT` artifact pass.

## Verification

- Windows GCC current CTest passed all 42 cases, including platform input,
  keyboard host ingress, F9 cancellation, Console/window, two-session, DOS
  keyboard, and FDD DOS-prompt coverage.
- `verify-keyboard-transport-surface` emitted
  `M5:T202:S1:KEYBOARD-TRANSPORT-SURFACE:OK`; the T201 host-cancellation gate
  passed in the same run.
