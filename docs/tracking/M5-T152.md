# M5 T152: MS-DOS MEM Fault Capture

## Result

The owner-local FDD smoke reached the normal DOS prompt, injected
`mem<Enter>` through the existing Win32 keyboard route, and deterministically
captured the first failure:

```text
CS:IP     096A:000000CE
linear    0000976E
bytes     DB E3 51 B9 14 00 E2 FE 59 33 C0 A3 58 00 D9
exception VCPUINS_EXCEPT_UD, code 0
```

`DB E3` is x87 `FNINIT`. The retained executor dispatches `DB` to
`UndefinedOpcode`; the immediate issue is missing x87 capability/modeling, not
an identified generic i386 integer decoder fault.

## Implementation

- `core_machine` owns a fixed 32-entry in-memory instruction window and a
  first-fault snapshot. No VM/VDM dependency, global state, raw recorder, or
  external reference dependency was added.
- The snapshot records execution point, 15-byte window, exception mask/code,
  general registers, and FLAGS. Reset clears it.
- `nxvm-core-machine-cpu-fault-diagnostic-smoke` verifies wraparound and the
  stable `DB E3` first-fault capture through the true `nxvm-core` target.
- `nxvm-vm-dos-mem-fault-smoke` runs the owner-local FDD fixture under a
  three-second prompt and two-second post-command budget.

## Follow-Up

T153 designs a profile-selected x87 presence/absence contract and a minimum
core-owned implementation. It must not replace `FNINIT` with a no-op or claim
full x87/i386 support.
