# M5 T140: Linux Platform Run-Handle Parity

| Subtask | Scope | Status | Evidence |
| --- | --- | --- | --- |
| S1 | Convert Linux Console workers to the T138 handle, join, and sole-destroyer contract | Active | Pending |

## Boundaries

- **Objective:** give Linux Console the same session-owned handle, worker-only
  reporting, cancellation, join, renderer/terminal teardown, and lease-release
  ordering as the completed Win32 path.
- **Non-goals:** native POSIX runtime verification on this Windows host, a
  window backend, VDM behavior, or any NXVM Console grammar change.
- **Reference:** `docs/planning/m5-platform-run-handle-contract.md` and T139.
- **Static gates:** no detached worker; no worker-side curses/terminal/lease
  release; every started thread is joined before backend finalization; former
  `lnxcStartMachine` entry is removed; hub calls only run-handle operations.
- **Handoff gate:** a POSIX maintainer configures GCC and runs Console stop,
  failed second-worker creation, terminal lease contention, and FDD DOS-prompt
  checks before claiming native runtime parity.
- **Stop:** stop if a Linux worker can free shared platform/session state, a
  new VM/VDM-specific core branch appears, or static source cannot demonstrate
  a single teardown owner.
