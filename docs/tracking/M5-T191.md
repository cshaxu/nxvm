## S1 Contract

`0x43` read-back uses active-low counter selection; `D5 == 0` latches count
and `D4 == 0` latches status. An unread status latch is returned before an
unread count latch and neither is overwritten by a later read-back command.
The count read retains its programmed RW byte order. The status snapshot is
`OUT`, null-count, RW, mode, and BCD; S2 records the retained model's explicit
limited OUT behavior rather than claiming a cycle-accurate waveform.

The behavioral reference is the Intel 8254 data sheet's Read-Back and Status
Read-Back sections. Bochs is not a source for this task.

## Applicable Rules And Evidence

- **Core ownership and dependency rules:** PIT storage/lifecycle stays in
  `core_machine`; S2 does not add a VM/profile dependency.
- **Wrapper discipline:** S2 does not add a second PIT, cache, or forwarding
  facade.
- **Compatibility protection:** every runnable task retains Console/debugger,
  FDD/HDD boot, and DOS-prompt evidence. No exception is requested.
- **Trace/source policy:** Bochs is comparison-only and bounded; it is never
  imported, linked, or used instead of owned probes. The 8254 primary contract
  comes from device documentation, not the Bochs implementation.

## Result

T191 S2 added core-owned status latches and output-state snapshots beside the
existing count latches. `0x43` read-back now selects counters active-low,
preserves unread count/status values, returns status before count, and retains
the programmed count byte order. No VM/profile dependency or PIT lifecycle
owner was added.

The remaining mode waveform, GATE, BCD-edge, and count-zero work is recorded
in `TODO.md`; it was deliberately not folded into read-back.
