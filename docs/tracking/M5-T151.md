# M5 T151: Keyboard Host Ingress Repair

## Problem

The Window backend could show a guest window while leaving the management
Console as the effective keyboard focus. This made a running Window session
appear unable to accept input, even though the guest keyboard provider and DOS
buffer were functional.

## Repair

After its Window becomes visible, the Win32 Window backend now requests the
foreground and keyboard focus for that guest window. The guest Window remains
the owner of its input route; no selected-session global or Console routing
was added.

## Verification

- `nxvm-vm-keyboard-host-ingress-smoke.exe` proves Win32 scan-code mapping
  reaches the session's BIOS keyboard buffer:
  `M5:T151:S1:KEYBOARD-HOST-INGRESS:OK`.
- `nxvm-vm-dos-keyboard-smoke.exe D:\fdd.img` boots DOS, injects
  `ver<Enter>` through the Win32 keyboard route, and observes guest text
  consumption: `M5:T151:S2:DOS-KEYBOARD:OK`.
- Full current GCC gates, retained Console lifecycle, and existing FDD
  DOS-prompt regression passed.
