# M5 T168: Core Vocabulary and CMake Clarity

## Scope

Close bounded non-behavioral cleanup from T162: standard-library vocabulary,
contract terminology, and the core CMake target relationship.

## Result

- `STD_MEMMOVE` is declared and implemented in the root C facade; VDM's
  keyboard queue no longer calls `memmove` directly.
- `contracts.md` now uses the actual `ntvdm64_status` and `core_machine`
  vocabulary.
- CMake exposes `ntvdm64-core-machine-primitives` and
  `ntvdm64-core-machine-runtime` aliases. The former is CPU/RAM/port storage;
  the latter adds the sole public core runtime. They do not represent two
  execution models.

## Verification

- GCC built `nxvm-0-5-0168` and the core executor smoke.
- The active Console lifecycle and VM session-manager smokes retain their
  results.
- A source scan finds no direct `memmove` use outside `type.c`.
