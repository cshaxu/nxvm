# M5 T192: 8042 KBC Compatibility

Status: complete.

## Objective

Replace the KBC placeholder with the approved 8042 keyboard-controller subset,
then move NXVM host-key delivery to its one KBC/BIOS route without changing
Console or debugger keyboard UX.

## S1 Decision

The only accepted input route is platform-normalized host event ->
default-profile layout mapper -> explicit core-machine scan-code ingress ->
core KBC FIFO/OBF/IRQ1 -> QDKEYB INT 09h `0x60` read -> BDA -> INT 16h.
The detail is normative in
[`m5-pc-compatible-device-plan.md`](../planning/m5-pc-compatible-device-plan.md).

The first controller subset is ports `0x60`/`0x64`, OBF/IBF, command byte,
controller commands `20/60/AA/AB/AD/AE/D0/D1`, keyboard ACK/reset/enable/
disable/identify, IRQ1, A20, reset request, and a 16-byte FIFO. It excludes
AUX/IRQ12, mouse, translation, scan-code-set switching, timing, and break-byte
emission.

## Boundaries

- `core/machine/kbc.*` owns controller and byte state. `core_machine` binds
  core PIC/A20/reset services and exposes one submit-scan-code contract.
- `vm/profile/default_profile` owns layout mapping and BIOS scan-to-BDA
  translation. It neither owns KBC state nor calls host APIs.
- VM composition connects normalized platform events to the mapper and submits
  one byte. It holds no KBC alias and contains no keyboard layout table.
- Platform normalizes events and owns no guest keyboard state.

## Planned Subtasks

- **S2:** implement core KBC state, ports, FIFO, commands, PIC/A20/reset
  binding, and focused controller smoke. A full FIFO returns
  `NTVDM64_STATUS_INVALID_STATE`; the old direct QDKEYB route remains.
- **S3:** introduce the profile mapper, route host input through KBC, make
  QDKEYB INT 09h consume `0x60`, remove direct host-to-BDA injection, and run
  two-session plus retained DOS keyboard evidence. Emit `nxvm_0_5_0192.exe`.

## Rules And Exit Criteria

Applicable rules: core ownership/dependency direction, one state owner, one
input route, provider freeze, wrapper discipline, and retained Console/
debugger/FDD-HDD compatibility. Stop for a second input queue, core-to-VM
dependency, host handle in KBC, user-visible control-key change, or need for
mouse/translation work.

S1 is complete when the command/status/FIFO/overflow/reset contract, topology,
source surfaces, probes, artifact rule, and stop conditions are recorded. It
creates no executable.

## Completed Subtasks

**S1:** The controller reference boundary is the AT-compatible 8042
command/status interface; the behavior is verified by owned port probes, with
Bochs used only to compare state decomposition. The default command byte is
`0x05`, deliberately leaving translation clear because this task submits fixed
set-1 bytes and defers translation.

**S2:** `core/machine/kbc.*` now owns the command byte, output port, status,
pending command/data state, scanning/controller enable state, and a 16-byte
FIFO. It serves both ports, commands `20/60/AA/AB/AD/AE/D0/D1`, keyboard
ACK/reset/enable/disable/identify responses, IRQ1 through the core PIC, and
the A20/reset output-port effect through core-owned RAM/CPU state. The focused
smoke emits `M5:T192:S2:KBC-CONTROLLER:OK`; the complete current GCC gate and
retained FDD prompt, DOS keyboard, FDD/HDD session checks also pass. The old
direct host-to-QDKEYB route deliberately remains until S3.

## S2 Exit Review

S2 meets its design exit: there is one controller state owner, no KBC alias or
VM callback, no host handle/thread or second queue, and no Console/debugger or
guest-keyboard behavior change. `docs/verification/m5-t192-s2-kbc-controller.md`
records the exact evidence.

## S3 Result And Exit Review

Platform backends now submit only normalized scan/virtual-key events. The
session request transport serializes them at the execution boundary; the
default-profile mapper returns the fixed set-1 make byte, and the core machine
submits that byte to its KBC. QDKEYB INT 09h reads `0x60`, translates the byte
to a BIOS code, updates BDA, and acknowledges IRQ1. INT 16h empty reads halt
the guest at the BIOS boundary; a later IRQ1 completes that read without a
host thread touching guest RAM. `core_machine_run()` now refreshes pending
interrupts before reporting an already-halted guest as waiting.

S3 meets the one-route, owner, and behavior exits: no direct host-to-BDA
write, no second keyboard queue, no host handle in core, no core-to-VM
dependency, and retained Console/debugger behavior. GCC gates, KBC controller
and route smokes, FDD DOS prompt/keyboard, FDD/HDD full-PC session, and
two-session isolation pass. `nxvm_0_5_0192.exe` prints the correct banner and
accepts `EXIT`. The result is recorded in
`docs/verification/m5-t192-s3-kbc-handoff.md`; deferred device work is in
`TODO.md`.
