# M5 T147: Shared Session Open And Selection

## Outcome

The retained NXVM Console now routes `SESSION LIST`, `SESSION OPEN`, and
`SESSION SELECT <id>` through `core/product/session/command.c`. The generic
command facility owns no VM state; it receives only the opaque manager and an
explicit output callback. The Console owns the output callback, and the VM
selected-machine provider borrows the selected opaque entry for each retained
machine command.

`OPEN` creates a stopped `vm_session` with independent in-memory state and
does not change selection. `LIST` emits copied snapshots in ascending ID order
and marks the unique selected session with `*`. `SELECT` accepts only a live
numeric ID. No close operation is implemented in this task, so there remains
no public route to an empty session table.
