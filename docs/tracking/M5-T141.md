## Boundaries

- **Objective:** remove the misleading core-machine type selection without
  changing the one actual executor or product behavior.
- **Non-goals:** move device lifecycle in this subtask, add a VM/VDM core type,
  remove VM aliases (T142), or change Console/debugger behavior.
- **Reference:** `docs/planning/m5-platform-run-handle-contract.md` T141
  constraint and `docs/verification/m5-t140-s1-linux-run-handle.md`.
- **Files/ABI:** `core/machine/machine.*`, its tests, VM session creation, and
  VDM minimal creation only.
- **Gates:** Windows GCC core executor/lifecycle, VDM-minimal session,
  two-session, Console lifecycle, and FDD DOS-prompt tests; source scan finds
  no `CORE_MACHINE_PROFILE_*` or `core_machine_enable_executor`.
- **Stop:** stop on a second executor/state copy, VM/VDM-specific core branch,
  lifecycle-order change, Console/debugger regression, or FDD DOS-prompt
  failure.

## S2 Boundary

S2 changed only the standard executor CPU/RAM/port lifecycle. `core_machine`
will prepare it during creation and finalize it during destruction; VM, VDM,
and test fixtures no longer call the three preparation functions. S3 owns the
remaining shared PIC/PIT/DMA/KBC/VADP lifecycle migration.

## Result

T141 is complete. `core_machine` unconditionally owns standard executor and
shared-device storage plus prepare/reset/refresh/finalize order. VM only binds
VM-specific devices, firmware, providers, and profile hooks; VDM follows the
same core creation path.
