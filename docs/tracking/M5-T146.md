# M5 T146: Core Product Session Manager

## Outcome

`core/product/session/manager.c` owns the opaque session table, ascending
numeric IDs, copied snapshots, and exactly one selected ID. VM composition now
supplies concrete creation/description/destruction callbacks; `vm/main.c`
creates and selects complete session `0` before entering the retained Console.
The old single-session Console target is replaced by a selected-machine
provider which borrows the manager selection only at each machine command.

The manager exposes no public close operation in this task. Consequently no
product API can create a no-session state. T148 will add close and enforce the
same invariant by rejecting an attempt to close the final live session.

## Migration Map

- `vm/composition/session/console_target.*` became `provider.*` and no longer
  owns a concrete session pointer.
- `vm/product/console_target.h` became `console_machine_provider.h`.
- Console context moved out of `vm_session`; `vm/main.c` owns the Console,
  manager, and selected-machine provider in that order.
- `core/product/session/manager.c` is generic: it has no VM/VDM includes,
  no guest execution loop, and no global/TLS state.
