# M5 T175: VM Session Owner-Alias Closure

## Confirmed Design

Before T175, `vm_session` embeds 18 direct state objects but also stores
permanent pointers to each. Initialization only assigns each pointer to its
embedded `*_storage` field; finalization only clears it. The aliases cover VM
devices; default-profile firmware/context; provider slots; presentation,
transport, wait, and platform objects; debugger context; and control state.

They are not runtime boundaries: no caller may replace them, no lifecycle
transfers, and no polymorphic implementation is selected through them. Their
removal makes direct session ownership visible in the type layout.

`core_machine *core_machine` remains a separately allocated opaque owner.
`debug_target` remains a lazy dynamic UI adapter with explicit finalization.
`control` becomes embedded because it has no heap-owned subresource.

## Execution Rule

T176--T184 migrate one owner group at a time, preserving initialization and
finalization order. A task stops at the first stale pointer, lifecycle change,
or retained behavior failure; it does not combine unrelated owner groups.

## Result

Design complete. No runtime source changed and no task artifact is produced.
T176 is the first implementation task and may begin only with its own bounded
subtask record.
