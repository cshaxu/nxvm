# M5 T144: Shared Product Session Management Design

| Subtask | Scope | Status | Evidence |
| --- | --- | --- | --- |
| S1 | Define shared session management, NXVM UX, future VDM adoption, source shape, interfaces, and bounded implementation tasks | Complete | `docs/verification/m5-t144-product-session-design.md` |

## Boundaries

- **Objective:** define the owner-approved shared product-session mechanism,
  its NXVM implementation sequence, and its future VDM adoption boundary,
  without changing runtime source or starting M6.
- **Non-goals:** VDM runtime/session implementation, DOS behavior, a new NXVM
  process CLI, CPU/device changes, guest media import, or implementation.
- **Rules:** product/module ownership; explicit provider contracts; one state
  owner and one execution path; no global/TLS selector; retained Console,
  debugger, and boot behavior; task/artifact/build hygiene rules in `RULES.md`.
- **Reference baseline:** M5 T143, including its retained Console, FDD
  DOS-prompt, two-session construction, and session-readiness gates.
- **API/source plan:** `core/product/session/` owns opaque registry and shared
  command tooling; `vm/composition/session/` and future
  `vdm/composition/session/` own concrete sessions/providers; the old
  single-session Console target migrates to explicit core session and VM
  selected-machine providers.
- **Session invariant:** the generic manager always has one or more live
  entries and exactly one selected entry; `CLOSE` rejects the final session.
- **Verification:** documentation cross-reference review, task numbering
  review, and source-boundary review only. This design task creates no EXE.
- **Stop:** stop for an unapproved retained-Console redesign, a second
  machine/executor proposal, `core/composition`, product ownership of
  selected-session state, or a VDM runtime scope expansion.
