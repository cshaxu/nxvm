# M5 T200: Host Keyboard-State Ingress

Status: complete.

## Objective

Make the VM session request transport the only path by which host
modifier/toggle snapshots reach the guest keyboard provider. Platform code may
sample host state and submit an ingress request, but only the session consumer
may apply it at the runner command boundary.

## Scope

- Remove the historical VM keyboard `apply_host_state` callback that lets a
  platform-facing transport mutate the provider directly.
- Give the platform run context one submission operation for host-state
  snapshots, bound by composition to the session-owned ingress transport.
- Coalesce only consecutive queued keyboard-state snapshots. A key press or
  another request remains an ordering barrier, so a later snapshot cannot move
  ahead of it.
- Add focused state-before/state-after-boundary and coalescing/order smokes,
  a static closure gate, and artifact `0.5.0200`.

## Non-Goals

- Do not change scan-code mapping, QDKEYB BIOS behavior, KBC behavior,
  keyboard layout, Console/debugger grammar, worker cancellation, or host
  display behavior.
- Do not claim Linux runtime verification. Linux retains source-contract
  parity; native build/runtime verification remains owner-environment work.

## Rules And Stop Conditions

- `vm_session` owns ingress and is its only consumer; `core_machine` provider
  mutation remains session-side only.
- Platform code must not call a provider or core keyboard API directly.
- Coalescing is bounded and preserves the FIFO position of every non-state
  request.
- Stop for a second input route, guest-state mutation before the command
  boundary, key/focus/toggle regression, Console/debugger UX change, or FDD
  DOS-prompt failure.

## Required Evidence

- Transport smoke proves adjacent snapshots coalesce to the newest value while
  a key press remains an ordering barrier.
- Session smoke proves a submitted snapshot leaves BIOS keyboard flags intact
  before the execution boundary and updates them after it.
- Static closure proves the old direct VM callback is absent, Win32 submits by
  run-context operation, and session consumption remains the provider mutation
  point.
- Current CTest gates and a `0.5.0200` Console `EXIT` artifact pass.
