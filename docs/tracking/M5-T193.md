# M5 T193: VADP CGA Text Controller Slice

Status: complete.

## Objective

Define and then implement one truthful CGA text-controller slice. VADP owns
guest-visible register, VRAM, dirty, and snapshot state; QDCGA remains
default-profile INT 10h firmware; composition alone converts a copied VADP
snapshot to a platform frame.

## S1 Scope

- Fix the supported CRTC text index subset through `0x3d4`/`0x3d5`:
  `0x0a`/`0x0b` cursor shape, `0x0c`/`0x0d` start address/page, and
  `0x0e`/`0x0f` cursor location.
- Fix `0x3d8` text mode, `0x3d9` color, stable zero text-slice `0x3da`
  status, and the `0xb8000` text window contract.
- Define one dirty generation and a caller-copied text scanout snapshot. Guest
  port/VRAM writes and QDCGA mode/cursor/page operations target that one state.
- Define unsupported graphics as a clear unsupported result, not a text-mode
  fallback or an implied graphics claim.

## Non-Goals

- No CGA graphics pixels, palette rasterization, EGA/VGA register families,
  raster timing, renderer replacement, DOS runner, or external ROM.
- No platform access to guest VRAM, VADP alias retained by the profile, or
  QDCGA-owned controller/snapshot state.
- No Console, debugger, host window, boot-media, or input-policy change.

## Source Boundary

- VADP owner: `src/core/machine/vadp.*` and required core machine interface.
- Firmware owner: default-profile QDCGA and BDA policy.
- Assembly boundary: VM composition's copied snapshot-to-platform-frame path.
- Platform consumes copied frames only; it never names or borrows VADP/VRAM.

Bochs may be consulted only for state decomposition and observable port/VRAM
behavior. The primary contract is device documentation plus owned probes. Its
global manager, direct GUI update, C++ plugin shape, source, and build are not
adopted.

## Planned Subtasks

- **S3:** use S2 evidence and named DOS probes to either admit a fully bounded

## Rules, Evidence, And Stop Conditions

Applicable rules: one state owner, core independence, provider freeze, copied
machine-snapshot/platform-frame boundary, wrapper discipline, source policy,
and retained NXVM compatibility. S2 evidence must include focused CRTC/mode/
color/status/B8000/snapshot tests, provider isolation, current GCC gates,
Console/window behavior, FDD/HDD boot, and DOS prompt checks. It must emit the
task artifact in `build/output/`.

Stop before code changes for a second video state/snapshot, profile-held
mutable VADP/VRAM alias, direct platform VRAM access, graphics scope expansion,
external source import, or a user-visible NXVM behavior change. S1 produces no
executable.

## S2 Result And Exit Review

`core/machine/vadp.*` now owns the bounded CGA text-controller state:
`0x3d4`/`0x3d5` indexes `0x0a`--`0x0f`, text-mode `0x3d8`, color `0x3d9`,
stable no-raster `0x3da`, B8000 visible-window reads, dirty generation, and a
copied text snapshot. The snapshot takes one or two contiguous RAM copies and
then compares core-owned cache state, so it retains the established one-
instruction VM run budget rather than performing a per-byte RAM call loop.

QDCGA no longer borrows VADP storage or creates a snapshot. It keeps only INT
10h/BDA policy and requests text mode, display-start, and cursor configuration
through `core_machine_profile_binding`. Composition binds the copied core
snapshot to the existing mailbox/frame conversion; platform code still sees no
VADP or guest-memory reference. Graphics mode requests are rejected by the
core text configuration and a graphics-selected `0x3d8` write is inert.

The focused `core-machine-vadp-text-smoke` emitted
`M5:T193:S2:VADP-TEXT:OK`, covering CRTC cursor state, color/status, B8000
content, dirty capture, and inert graphics selection. Current GCC gates,
QDCGA boundary, mailbox/mode, FDD/HDD session, two-session, FDD DOS-prompt,
and DOS `ver<Enter>` keyboard checks pass. `nxvm_0_5_0193.exe` prints the
expected banner, accepts `EXIT`, and returns zero.

## S3 Graphics Admission Review

**Decision: defer CGA graphics.** There is no owned DOS graphics program probe,
no defined `320x200x4` address/scanline/palette contract, and no pixel-frame
snapshot type. Implementing pixels now would turn a bounded text task into an
unverified graphics project. T193 therefore retains the S2 unsupported result.

The next graphics task, when activated, starts with only CGA `320x200x4` and
must first freeze B8000 graphics addressing, `0x3d8`/`0x3d9` semantics,
palette, copied pixel-scanout payload, port/memory/frame probes, one real DOS
program fixture, and the existing boot/Console regressions. EGA/VGA are later
independent admissions: memory windows, sequencer, graphics/attribute
controller, DAC, then planar/latch behavior. These unimplemented capabilities
are recorded in `TODO.md`. S3 creates no executable.
