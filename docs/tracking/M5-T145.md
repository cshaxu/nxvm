| Subtask | Scope | Status | Evidence |
| --- | --- | --- | --- |
| S1 | Move VM session-composition units and add generic core-product session contracts without changing the single-session runtime path | Complete | `docs/verification/m5-t145-session-composition-contract.md` |

## Boundaries

- **Objective:** make the approved `core/product/session` and
  `vm/composition/session` source shape real while retaining the existing
  single-session Console target and lifecycle behavior.
- **Non-goals:** create a manager, change `main`, add `SESSION` commands,
  alter device/media policy, add VDM runtime behavior, or remove the old target.
- **Rules:** `core/product` remains opaque and product-neutral; composition
  remains the sole concrete-session owner; no duplicate executor/state,
  global/TLS selector, or retained Console/debugger/FDD behavior change.
- **Source map:** each VM composition unit moves with `git mv` into
  `vm/composition/session/`; `session_control` becomes `control`,
  `session_execution_context` becomes `execution`, `session_lifecycle` becomes
  `lifecycle`, `session_runner` becomes `runner`, `display_bridge` becomes
  `display`, and `block_provider` becomes `block`.
- **Gates:** dependency DAG, C facade headers, current GCC build, retained
  Console lifecycle, two-session construction, and FDD DOS prompt.
- **Artifact:** build `nxvm_0_5_0145.exe` after all gates pass.
- **Stop:** stop on changed Console/debugger grammar or output, FDD prompt
  regression, a core-to-VM dependency, or a second session/executor path.
