# M5 T163: Frozen Core API Boundary Design

## Result

T163 turns the T162 P1 raw-borrow finding into a bounded implementation plan.
It does not change code, Console grammar, boot, debugger behavior, or media
policy, so it emits no task executable.

## Confirmed Facts

- `core_machine_executor_*_borrow` currently returns mutable executor objects
  without lifecycle validation in
  [`machine.c`](../../src/core/machine/machine.c:129).
- The selected-session Console callback reaches raw RAM allocation through
  [`console_machine_adapter.c`](../../src/vm/composition/session/console_machine_adapter.c:39).
- `core_machine_get_cpu_state()` rejects only `INITIALIZED`, while
  `core_machine_get_cpu_diagnostic()` has no lifecycle guard in
  [`machine.c`](../../src/core/machine/machine.c:186).
- `core_machine_config.memory_bytes` already defines RAM capacity at creation
  in [`machine_interface.h`](../../src/core/machine/machine_interface.h:33).
- `vm_session` owns one opaque `core_machine` plus VM-only device/profile
  storage in [`session.h`](../../src/vm/composition/session/session.h:62).

## Decision

- Configuration-only mutable borrows are short lived, available only before
  freeze, and are never a product-command API.
- Read-only CPU/fault observation is a copied paused-boundary payload.
- Changing RAM reconstructs the selected stopped session's machine graph
  transactionally while retaining one `vm_session` identity; it does not resize
  the existing RAM allocation.
- Reconstruction resets guest state by design and preserves only frozen
  configuration plus copied explicit media descriptors.

The detailed contract and T164--T168 execution breakdown are in
[`m5-t163-s1.md`](../planning/subtasks/m5-t163-s1.md).

## Rules Review

- `RULES.md` machine/session rules: applied. One `core_machine` owns guest
  state; no duplicate runnable core or cached raw object is permitted.
- `RULES.md` abstraction/wrapper discipline: applied. The session remains the
  sole concrete identity rather than adding a forwarding replacement wrapper.
- `RULES.md` scope/testing governance: applied. T163 is design-only and has no
  artificial executable; all follow-up behavior tasks carry retained Console,
  debugger, and FDD gates.
