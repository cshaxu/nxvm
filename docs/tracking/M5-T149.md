# M5 T149: Concurrent Window Sessions

## Outcome

The retained NXVM product path supports multiple manager-owned Window sessions
without a new executor or UI ownership model. Each `vm_session` retains its
own platform run context and run handle; manager selection changes only which
machine commands target. A Window start returns to the management Console,
allowing another selected Window session to start.

Console/terminal execution remains intentionally process-exclusive. The shared
host-surface lease rejects a second owner and is not relaxed for multi-session
support.

## Verification

- `nxvm-vm-multi-window-session-smoke.exe` created two manager-owned VM
  sessions, started both in Window mode, stopped the first while verifying the
  second remained active, then stopped/finalized the second. It printed
  `M5:T149:S1:MULTI-WINDOW:OK`.
- `ntvdm64-core-platform-host-surface-smoke.exe` printed
  `M5:T89:S1:HOST-SURFACE-LEASE:OK`, preserving process-exclusive Console
  ownership.
- Full GCC gates and FDD DOS-prompt regression passed.
- `build/output/nxvm_0_5_0149.exe` retained the Console entry/exit path;
  SHA-256:
  `0747CE9D0C7BAD257FAD49C4775CC12FCA579F3969E87C6FCDBC408387C98DD2`.

## Rules Exit Check

Window worker/renderer state remains session-owned through the existing run
handle. Generic core session code did not gain platform policy, and the test
uses the one VM composition session path rather than a parallel fixture.
