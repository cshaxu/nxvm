# M5 T162: Structural Closure Audit

## Confirmed Closure

The real NXVM path is singular:

```text
vm/main -> core_product_session_manager -> vm_session
        -> vm_session_runner_run -> core_machine_run
        -> core_machine_cpu_execution_refresh
```

`core_machine_run` is called by the VM runner and the paused debugger wrappers
only. No VM-side instruction refresh loop or second live machine was found.
The VDM path remains the intentional non-runnable `vdm_session`/DOS-minimal
scaffold with no product entry.

The dependency gate reports zero current migration edges, the executor gate
reports `M5:T86:EXECUTOR-CLOSURE:OK`, and the readiness inventory finds only
the two documented process-exclusive Console leases. There is no production
`_Thread_local` or implicit current-object selector. `core` has no `vm`/`vdm`
include.

T161 is structurally intact: the ordering coordinator contains only calls to
the device and profile components, while their stateful work remains in their
separate files.

## Findings

### P1: Frozen Core Boundary Still Has Raw Escape Hatches

`core_machine_executor_*_borrow` is a public mutable borrow surface. In
particular, the retained Console `DEVICE ram` adapter calls
`core_machine_memory_allocate_for(core_machine_executor_memory_borrow(...))`
in [`console_machine_adapter.c`](../../src/vm/composition/session/console_machine_adapter.c:39), after the
machine has frozen its topology. This contradicts T160's reconstruction-only
contract and can race a running session. `core_machine_get_cpu_state` and
`core_machine_get_cpu_diagnostic` also lack the `PAUSED` guard used by public
memory/port APIs, so their boundary contract is weaker than documented.

Follow-up: T163 designs one explicit configuration/reconstruction path and a
copied observation contract before any behavior change.

### P1: Committed Machine-Local Media Policy

The default session factory still inserts `d:/fd.img`, `d:/hd.img`, or
`/Users/xha/*` in the former mixed provider source.
This violates the repository's no-machine-local-path rule and makes session 0
depend on an undocumented host fixture.

Follow-up: T164 defines and implements an explicit no-media/default-fixture
policy while retaining the existing Console media commands.

### P2: Remaining Mixed Console Adapter

The former mixed provider source mixed the
session factory (`open`/`describe`/`close`) with all selected-session Console
machine callbacks. The manager selection is explicit and valid, but the file
name and mixed responsibilities are not. Split factory and Console adapter
sources in T165.

### P2: Contract/Vocabulary And Build Naming Drift

`contracts.md` still refers to nonexistent uppercase `CORE_MACHINE_*` contract
types and a nonexistent `core_machine_set_cpu_state`; the source has
`core_machine_config`, `core_machine_lifecycle`, and a read-only CPU-state
surface. [`dos_minimal.c`](../../src/vdm/machine/dos_minimal.c:48) still calls
raw `memmove`. CMake's `nxvm-core` plus `nxvm-core-machine` target split forms
one linked core, but its names make that relationship needlessly ambiguous.

Follow-ups: T166 reconciles contract/vocabulary; T167 clarifies CMake target
roles. Neither finding is a second runtime machine or executor.
