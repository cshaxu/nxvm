# M5 T159: Core Lifecycle Boundary Audit

## Result

T159 confirms that the lifecycle arrangement requested for the shared core was
already implemented by T141 and had only been contradicted by a stale TODO
entry. `core_machine_create`, `core_machine_reset`, `core_machine_run`, and
`core_machine_destroy` own CPU, RAM, port, PIC, PIT, DMA, KBC, VADP, and FPU
lifecycle order.

VM composition creates and owns only CMOS, FDD/FDC/HDD, debug state, default
firmware, and provider bindings. It binds those objects after core creation
and before provider freeze; it does not initialize, reset, refresh, or
finalize a generic core device. VDM has no such direct generic-device lifecycle
call either.

`nxvm-core-lifecycle-ownership-closure` scans `src/vm` and `src/vdm` for the
generic core-device lifecycle APIs and fails if any reappear. The existing
sequence is therefore fixed as:

```text
create core -> create/bind product objects -> freeze -> reset -> run
            -> finalize product objects -> destroy core
```

## Follow-Up

Public lifecycle hardening and further composition separation remain separate
audits. They must preserve this fixed phase model rather than introduce a
VM-between-core-devices hook.
