# M5 T171: Checked RAM Range And Provider Access

## Result

- `t_ram` now distinguishes installed bytes from its backing capacity; ordinary
  RAM is exactly `[0, installed_bytes)`.
- Physical and real-mode accesses fail outside that range. The historical
  modulo fallback and implicit high-address alias are removed.
- The default VM profile registers one frozen, explicit 16-byte mapping from
  the architectural 80386 reset vector `FFFF_FFF0` to its loaded BIOS image at
  `000F_FFF0`. It is profile configuration, not a generic RAM alias.
- BIOS, QDDISK, QDCGA, and DOS observations use checked copy/read/write APIs;
  provider code retains no guest backing pointer.
- QDCGA compares a checked guest snapshot with its VADP-owned host buffer, so
  presentation remains bounded without exposing guest RAM.

## Verification

- `nxvm-core-machine-ram-port-context-smoke` proves installed boundaries, A20
  behavior, explicit reset-vector mapping, mapping freeze, and isolated RAM/
  port state.
- `nxvm-vm-qdcga-boundary-smoke`: `M5:T40:S1:QDCGA-BOUNDARY:OK`.
- `nxvm-vm-dos-prompt-smoke D:\\fdd.img`:
  `M5:T70:S2:DOS-PROMPT:OK`.
- Static scan confirms `core_machine_memory_real_address`, `connect.pBase`, and
  non-core `connect.backing` uses are absent.
