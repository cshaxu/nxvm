## Boundaries

- **Objective:** remove the `vm_session` raw alias map for `core_machine`
  internals without copying guest state or changing NXVM Console/debugger
  behavior.
- **Non-goals:** add a second machine, expose core storage to product UI,
  change guest execution, or redesign VDM DOS behavior.
- **Reference:** T142 exit standard in
  `docs/planning/m5-platform-run-handle-contract.md`.
- **S1 API shape (superseded by S5):** the temporary composition-owned access
  record was removed because it was a pure forwarding facade. Firmware/profile
  bindings still receive only the capability they need; product code reaches
  CPU/RAM only via existing debugger/target or composition callbacks.
- **Gates:** two-session, core executor, debugger target/pause, Console
  lifecycle, FDD DOS prompt, and source scans for raw alias fields and direct
  lifecycle bypasses.
- **Stop:** stop on copied/cached core state, a core-to-VM/VDM include, a
  second executor, Console/debugger behavior change, or FDD DOS-prompt failure.

## S5 Scope

- **Objective:** delete `vm/composition/machine_access.*`; it is a pure
  forwarding facade over `core_machine` borrow APIs and is therefore not a
  valid ownership boundary.
- **Allowed surface:** only `vm/composition` may borrow core execution/shared
  device capabilities directly, exclusively to bind VM providers/profile
  firmware or construct the existing debugger target. Product/platform peers
  continue to receive their existing target/provider contracts.
- **Non-goals:** cached aliases, new core state, a VM-side executor, changes
  to Console/debugger commands, or a different boot flow.
- **Gates:** source scan proves no `machine_access` source or symbol remains;
  dependency/ownership gates, executor storage, two-session, debugger/pause,
  Console lifecycle, and FDD DOS-prompt regressions pass.

## S5 Result

`machine_access.*` and the session's `core_access` state are deleted. The
core-owned `machine_interface.h` now declares the non-owning borrow contract;
only `vm/composition` calls it while binding VM providers/profile firmware or
building the existing debugger adapter. The current task artifact is rebuilt
as `nxvm_0_5_0142.exe`.

## S1 Result

`vm_session` no longer stores CPU, CPU-instruction, execution, RAM, or port
aliases. `vm_composition_machine_access` stores only the owning
`core_machine*` and obtains each capability on demand. Composition and the
debug target use that bounded contract; it creates no state copy or lifecycle
bypass.

## S2 Result

PIC/PIT/DMA/KBC/VADP aliases are also absent from `vm_session`. VM-only FDC
and profile binding borrow the needed shared-device capability through the same
composition access record; no device storage is duplicated.

## Result

T142 is complete. The debugger target remains target-local while product UI is
limited to the debug target contract. `vm_session` holds only one
`core_machine*`, not raw aliases or a forwarding composition-access record.
`vm_session_execution_context` now holds only its explicit `vm_session*`
callback owner, not stale CPU/RAM/port aliases.
