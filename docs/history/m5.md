# M5 Historical Summary

This historical summary records completed M5 work. It does not define current
state, architecture, scope, or task priority; see [Project Status]
(../planning/status.md) and the [M5 Closure Checklist]
(../planning/m5-closure-checklist.md) for those authorities.

## Archived T283 Closure

T283 extended the VM-free FDC/HDC media corpus, retired unused unsafe HDD CHS
transfer state, and made resident-media persistence failure-preserving. FDD
and HDD now write a complete, same-directory, exclusively created temporary
file before replacing the requested target. A pre-existing temporary candidate
is never truncated or removed by another save attempt; a write, close, or
replace failure leaves the mounted medium published.

The focused corpus retains a temporary-name collision, verifies the candidate
remains intact, and proves a successful replacement plus rejected invalid save
input. The source gate rejects direct target truncation in FDD/HDD persistence.
Full 110/110 CTest and 42 static/governance gates passed. `vm-0-5-0283` is
`build/output/nxvm_0_5_0283.exe`, SHA-256
`81CF4D6646C2B38A781F0D58B3FBAB29505D8EFE919A6375D35FA53DA83F9736`.

## Archived T279 Closure

T279 retired the unbounded `STD_SPRINTF` facade and its `vsprintf` path.
`STD_SNPRINTF` now has explicit zero-capacity, truncation, NUL-termination, and

The source gate rejects `STD_SPRINTF`, `vsprintf`, and `sprintf` in production
source. The dedicated formatter corpus covers exact output, truncation, zero

## Archived T269 Closure

T269 admitted the first bounded Level-3 DMA visibility slice without creating
a second scheduler or bus state machine. `core/machine/dma` now advances every
admitted memory-to-memory, demand, single, and block transfer by at most one
unit per DMA clock grant. `core_machine` retains the only ordering point:
completed CPU instruction, elapsed ticks, DMA, PIT, VADP, KBC, frozen VM
providers, then PIC visibility. VM FDC remains the DMA2 provider and never
borrows RAM or advances time itself.

The S4 core channel corpus directly proves block, demand, single, and
memory-to-memory first/second grants, terminal count, mask/re-request, and
the primary-through-secondary cascade route. Demand and single require a new
request for their second byte; M2M terminal cleanup clears both software
requests before arbitration can resume. The FDC corpus retains
DOR/DRQ/result/IRQ6 behavior. The DOS fixture performs the same FDC DMA2 read from the temporary system image under
`core_machine_run()` quanta of one and 128 instructions; it requires identical
guest RAM, IRQ record, motor-off result, and terminal result. It also waits
for the real FDC result phase, not an IRQ count alone. This exposed and closed
a fixture-observation bug rather than a guest-state shortcut.

Generic memory/I/O wait states, CPU HOLD, instruction-internal stalls,
prefetch, host-clock timing, and cycle-exact claims remain deferred.
