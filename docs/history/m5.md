# M5 Historical Summary

M5 is **open**. Its current closure authority is the
[M5 Closure Checklist](../planning/m5-closure-checklist.md); current work is
recorded only in [Project Status](../planning/status.md). This document
summarizes completed work and does not define current architecture, scope, or
task priority.

## Archived T277 Closure

T277 removed the retained ATA PIO controller's direct `t_hdd` pointer and raw
image-field access. Its VM-owned controller now consumes frozen registry query,
copied geometry, and copied read/write operations under the HDD identity.
Present/read-only/range/provider failures retain the established ATA abort or
ID-not-found outcomes; CHS, LBA28, count-zero, SRST, IRQ14 acknowledgement,
and PIO data sequencing are unchanged. ATA remains under `vm/machine` until
the separate T278 location migration.

The ATA boundary gate now rejects direct HDD storage vocabulary. HDC port,
ATA DOS read/write, HDD boot, and the full 108/108 current CTest matrix passed.
`vm-0-5-0277` is `build/output/nxvm_0_5_0277.exe`, SHA-256
`EA52F19ED01338A46BAEF1A3F20432136605A30F64C7EDC2B0CC4E47FB00E0CE`.

## Archived T276 Closure

T276 moved the neutral 8272A-compatible state machine from `vm/machine` into
`core/machine` by `git mv`. The one controller instance is now
`core_machine.shared_fdc`; core owns its reset, scheduler refresh, and teardown.
VM composition borrows it only while `INITIALIZED` to bind default-PC/AT port,
IRQ6, DMA2, and frozen FDD media-registry data. The FDC POST and INT assembly
remain default-profile firmware.

The core-only FDC fixture contains no VM vocabulary and proves the frozen
media/DMA/PIC/port binding and a real VERSION port transaction. Retained FDC,
DOS, PC/AT, and session-owner regressions passed with the full 108/108 current
CTest matrix. `vm-0-5-0276` is `build/output/nxvm_0_5_0276.exe`, SHA-256
`D939FEB5F590996B94A47E4C08520D2662693BE8448AB4A333F2C462A261D50D`.

## Archived T274 Closure

## Archived T273 Closure

T273 moved the single mutable MC146818-compatible register/calendar/tick/IRQ
mechanism from `vm/machine/cmos.*` to `core/machine/rtc.*`. The core device
owns no PC/AT port number, NMI policy, BIOS/BDA state, host time, or firmware.
VM composition now owns the thin profile-derived 70h/71h provider: its 70h
write applies bit 7 through the existing core NMI operation and delegates the
lower seven-bit register index; 71h delegates data access. Default-ROM CMOS
POST/timer assembly remains under default-profile firmware.

The core-only RTC smoke verifies tick advancement, IRQ8 assertion and register
C acknowledgement, plus retained NVRAM across reset. The retained VM corpus
verifies the PC/AT port/NMI adapter. The ownership and RTC boundary gates were
updated to reject VM policy in core and a VM mirror of RTC state. `vm-0-5-0273`
passed static/ownership checks and 106/106 CTest cases. The developer artifact
is `build/output/nxvm_0_5_0273.exe`, SHA-256
`5144E277818E960380AA31B92DD1D66659ADE75F18197FE068098A0081D3E5D6`.

## Archived T272 Closure

T272 made the retained VM FDD and HDD backing objects the only two providers
bound into the frozen `core/machine` media registry. Default-profile firmware
now receives copied HDD geometry through that registry; the old one-slot block
API, its composition bridge, and the HDC geometry shim are deleted rather than
retained as a forwarding facade. FDD/HDD still own bytes, CHS, insertion,
read-only state, and generation. FDC and HDC intentionally retain their direct
backing-object calls until their separately bounded T275 and T277 decouplings.

The focused corpus proves both identities, copied FDD/HDD geometry, format
generation, logical-sector range behavior, and retained FDC/HDC port behavior.
The final source sweep found no block API, cached firmware geometry, or second
media owner. `vm-0-5-0272` passed static/ownership checks and 105/105 CTest
cases. The developer artifact is `build/output/nxvm_0_5_0272.exe`, SHA-256
`3E4CF6782886C043E797EBECA4D6A4EB61399660E3F13291673B8696B679F99E`.

## Archived T271 Closure

T271 added the sole policy-free `core/platform` backing-resource contract
needed by the later VM media adapter. It accepts only a composition-created
provider/context borrow and exposes copied size, byte-range read/write, flush,
and synchronous one-time close. Typed results distinguish short transfer,
read-only, invalid range, transient/permanent failures, unsupported work, and

Existing copied input and cancellable-wait contracts remain unchanged.

The fake-provider corpus verifies size, short read, copied write, typed
transient flush failure, exact-once close, and complete post-close rejection.
The source sweep found no policy vocabulary or second cancellation mechanism in
the new core/platform surface. `vm-0-5-0271` passed static/ownership checks and
104/104 CTest cases. The developer artifact is

## Archived T270 Closure

T270 froze a profile-neutral, multi-device `core/machine` media-provider
contract without changing the retained NXVM FDD/HDD runtime path. Its registry
binds stable opaque identities only during configuration, freezes before
reset/run, holds only a borrow of composition-owned provider state, and exposes
copied media information plus byte-range, logical-sector, format, and flush
operations. Typed media results distinguish absent, changed, read-only,
invalid-range, transient, permanent, and unsupported outcomes. The registry
never returns provider backing pointers and contains no path, host handle,
mount policy, controller state, or media-byte cache.

The core-only fake-provider smoke proves two-device binding, duplicate and
post-freeze rejection, absent media, byte and sector I/O, generation after
format, flush observability, and read-only/range/transient/permanent failures.
The source sweep confirms that the legacy single `block_provider_slot` remains
only as the default-ROM HDD geometry bridge; FDC and HDC still directly own
their retained VM backing access. T272, not a forwarding wrapper, is the only
authorized removal path for that legacy boundary.

`vm-0-5-0270` passed static/ownership checks and 103/103 CTest cases. The
developer artifact is `build/output/nxvm_0_5_0270.exe`, SHA-256
`C9EF5CB901CB8B006FD5FBCC61F1E175AAAD3A74402E83D918464B35C80FF8F7`.

## Archived T269 Closure

T269 admitted the first bounded Level-3 DMA visibility slice without creating
a second scheduler or bus state machine. `core/machine/dma` now advances every
admitted memory-to-memory, demand, single, and block transfer by at most one
unit per DMA clock grant. `core_machine` retains the only ordering point:
completed CPU instruction, elapsed ticks, DMA, PIT, VADP, KBC, frozen VM
providers, then PIC visibility. VM FDC remains the DMA2 provider and never
borrows RAM or advances time itself.

The S4 core channel corpus directly proves block, demand, single, and
memory-to-memory first/second grants, terminal count, mask/re-request, and
the primary-through-secondary cascade route. Demand and single require a new
request for their second byte; M2M terminal cleanup clears both software
requests before arbitration can resume. The FDC corpus retains
DOR/DRQ/result/IRQ6 behavior. The DOS fixture performs the same FDC DMA2 read from the temporary system image under
`core_machine_run()` quanta of one and 128 instructions; it requires identical
guest RAM, IRQ record, motor-off result, and terminal result. It also waits
for the real FDC result phase, not an IRQ count alone. This exposed and closed
a fixture-observation bug rather than a guest-state shortcut.

Generic memory/I/O wait states, CPU HOLD, instruction-internal stalls,
prefetch, host-clock timing, and cycle-exact claims remain deferred.
`vm-0-5-0269` passed static/ownership checks and 102/102 CTest cases. The
developer artifact is `build/output/nxvm_0_5_0269.exe`, SHA-256
`D7AF67A4D1E48D2065A246996487AFC1763E760354CD54F4712B2E88752BB80F`.

## Archived T268 Closure

T268 made default-PC/AT FDC readiness require selected drive 0, DOR NRS,
present media, and that drive's ME0 bit. The sole mutable motor state remains
the FDC DOR; FDD still owns only media bytes and insertion generation. The
default ROM POST writes `1Ch` through the existing DOR port, so FDD boot stays
on the real controller route. No spin timing, BDA timeout, multi-drive, or
host-time behavior was admitted.

The T268 port corpus proves ME0-off and ME1-only no-data/IRQ6/SENSE results
without DMA RAM mutation, then ME0-on READ TRACK recovery. Its DOS COM fixture
first records a motor-off READ ID failure, then starts the retained DMA2 track
read after guest DOR `1Ch`; it emits `M5:T268:S3:FDC-MOTOR:DOS:OK`. The sweep
covered each readiness consumer, DOR initialization, and DMA assertion site;
the omitted motor predicate was the only production hit.

`vm-0-5-0268` passed static/ownership checks and 102/102 CTest cases. The
developer artifact is `build/output/nxvm_0_5_0268.exe`, SHA-256
`9D4BBC7A3A5684FA1D5CDD2778F03D32040879740ADD6474F9CB08623455AEE1`.

## Archived T267 Closure

T267 added the bounded standard PS/2 AUX configuration/status plane at the
sole per-machine `core/machine/kbc` owner. `F3h` admits sample rates
`10,20,40,60,80,100,200`; `E8h` admits resolution `0..3`; and `E9h` returns
the contiguous AUX-origin sequence `FAh, status, resolution, sample-rate` via
the retained `D4h -> 60h -> FIFO -> IRQ12` route. The controller's D4 routing
state and the AUX parameter wait are separate states, preventing an AUX
parameter from overwriting controller routing. `F6h`, `FFh`, and cold reset
retain the documented defaults. Wheel, remote mode, scaling effect, resend,
and host policy remain deferred in `TODO.md`.

The similar-issue sweep covered every production AUX command, delayed response,
pending-state, and host-report admission site in `src/core/machine/kbc.*`, plus
the core and DOS fixtures. The only production hit was the former shared D4
and AUX parameter state; it is fixed. No VM, platform, firmware, or DOS API
shortcut was found or added. The focused port probe emits
`M5:T267:S1:AUX:PORT:OK`; the DOS fixture starts from the FDD image, records
the guest IRQ12 bytes `FA AA 00 FA 00 FA FA FA FA FA FA 20 03 C8 29 05 FD`, and
emits `M5:T267:S3:AUX:DOS:OK`.

`vm-0-5-0267` passed static/ownership checks and 102/102 CTest cases. The
developer artifact is `build/output/nxvm_0_5_0267.exe`, SHA-256
`6D305FB4297D3896781C7ACF03EAE9ADC38EF9CA823AD00DF641759CEEFD8481`.

## Completed Work

- **T208--T216:** made the default PC/AT profile declarative; retired firmware
  portals; established ATA PIO, fault outcomes, and core PIC-owned IRQ
  delivery while preserving retained boot, Console, and debugger behavior.
- **T217--T227:** established deterministic elapsed-time scheduling, PIT and
  keyboard-controller behavior, and bounded CPU/host-input regression probes.
- **T228--T242:** added bounded CGA/EGA presentation, AUX mouse, DMA/FDC,
  CMOS/RTC, ATA, and system-image corpus coverage through project-owned probes
  and the retained full-PC regression matrix.
- **T243--T247:** established checked physical-memory routing, frozen
  undefined-instruction transitions, immutable ROM mappings, atomic entry
  plans, and the corrected full artifact/gate selection.
- **T248--T252:** admitted copied input, presentation, and cancellable-wait
  boundaries, then consolidated the sole VM composition lifecycle without
  changing retained product behavior.
- **T253:** extended the VM-owned ATA PIO controller through one admitted
  multi-sector task-file progress contract, with port and owner-built DOS
  round-trip coverage.
- **T254:** admitted the VADP-owned digital `640x200x2` CGA slice, default-ROM
  mode `06h`, and a boot-image regression that returns to text mode through
  normal video ports.
- **T255--T256:** froze the machine-profile admission contract, then replaced
  the PIT-only divider with per-machine integer rational clock domains for DMA,
  PIT, VADP, KBC, and frozen VM providers. This is Level 1 relative device
  timing, not instruction-, bus-, or cycle-exact emulation.
- **T257:** admitted a GDT-only, ring-0, 16-bit 80286 protected-mode corpus:
  real-mode `LGDT`/`LMSW`, code/data/stack selector loads, same-CPL far
  transfers, diagnostic `#GP`/`#NP`/`#SS`, and profile-form rejection. It
  deliberately does not claim broad privilege transitions, 32-bit semantics,
  or Windows compatibility.
- **T258:** admitted only a 80386 ring-0 4 KiB paging path: core-owned
  PDE/PTE translation through checked physical memory, A/D updates,
  non-present `#PF` with retained CR2, and narrowed CR0/CR2/CR3 forms. CPL3,
  paging permissions, TLB behavior, TSS I/O, task switching, and general
  32-bit compatibility remain deferred.
- **T259:** admitted a bounded common 80286/80386 16-bit privilege subset:
  CPL3 software `INT` through DPL-permitted gates, `LTR`-loaded 16-bit TSS
  `SS0:SP0` stack switching, paired outer `IRET`, and one observable `#GP`
  gate-delivery route. It excludes generic hardware/IDT delivery, 32-bit
  frames/gates, CPL3 paging, TSS I/O, LDT, and task switching.
- **T260:** admitted a 80386 32-bit-TSS I/O permission map through the
  existing CPL3 path. Allowed and denied byte I/O, truncated multi-byte map
  spans, 80286 no-map behavior, and the `CPL <= IOPL` bypass are covered;
  task switching and all broader TSS semantics remain deferred.
- **T261:** admitted only CPL0 far `JMP` between present GDT 16-bit TSS
  descriptors under both 80286 and 80386 profiles. The core executor saves and
  restores the bounded task state, transitions busy descriptors, and retains
  `#GP`/`#NP`/`#TS` diagnostics on invalid, unavailable, busy, or short TSS
  targets. S5 restores task B's `SREG_STACK` cache classification and locks
  its `#SS` limit path. Task gates, far CALL, nested/IRET task return, LDT,
  32-bit TSS, and switching under paging remain deferred.
- **T262:** admitted an exact-8087 finite `m32real` baseline through the
  existing ESC decoder: owned control/status/tag/TOP state, `FNINIT`, bounded
  load/store and register arithmetic, explicit unsupported outcomes, and
  pending-unmasked-exception `FWAIT -> #MF`. It retains FPU=none ESC
  consumption and makes no 80287/80387, broad IEEE, environment, or
  protected-mode FPU claim.
- **T263:** admitted only the existing 80286 protected-mode `ARPL r/m16,r16`
  form after a corpus proved that its metadata required 80286 but the executor
  incorrectly rejected it below 80386. The core-only corpus covers register
  and ES-prefixed memory destinations, both RPL/ZF outcomes, lower-profile and
  real-mode `#UD`, and rejected-execution atomicity. Other 286/386 instruction
  families remain individually corpus-gated. S4 then aligned the software-
  interrupt contract with the retained real-mode IVT and bounded protected
  16-bit IDT routes, and moved the unrelated descriptor-vocabulary debt from
  an obsolete inline task marker into the TODO ledger; it changes no runtime
  behavior or artifact. S5 corrected not-present gate and target-code
  classification to `#NP`, admitted the matching bounded `#NP` IDT handoff,
  and made the outer privilege-stack transition preflight its candidate
  caches, descriptor writes, entry fetch, and entire frame before CPU-state
  commit. The negative corpus retains the pre-transition CPL/CS/SS/SP on a
  too-small target stack. S6 fixed synchronous IDT error-code `EXT` handling
  and added a valid-but-not-present vector-13 gate corpus for `#NP(0x006a)`;
  original terminal-fault retention remains unchanged when an exception's own
  gate cannot be entered.
- **T264:** closed the default PC/AT owner/path audit by replacing the CMOS raw
  CPU borrow with a narrow callback, routing QDCGA reset through core bindings
  and guest ports, and removing an unused firmware registry.
- **T265:** added deterministic, profile-owned instruction-cost attribution
  for a bounded corpus while retaining zero default-PC/AT surcharges until a
  calibration corpus admits nonzero values.
- **T266:** closed bounded VADP CRTC cursor/page/status behavior and copied
  column/row coordinates, with retained DOS/video, graphics, and product
  regressions.

Each completed task's detailed contract, command output, artifact hash, and
provenance remain recoverable from its Git commit. M5 Td S23, Td S27, Td S30,
and Td S31 retired completed planning records from the working tree so that
planning contains only active work and closure authorities.
