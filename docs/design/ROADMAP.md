# Roadmap

Milestones define outcomes, not task allocation. See [Queue](../states/QUEUE.md)
for proposals and [Current](../states/CURRENT.md) for implemented status.

## M0: Governance Reset

Retain the historical ownership, source, documentation and verification foundation.

## M1: Preserve The NXVM Baseline

Retain the historical bootable baseline and evidence before structural change.

## M2: Design The Shared Foundation

Retain the historical neutral components and composition-boundary design.

## M3: Refactor The Shared Foundation

Retain shared machine and product capabilities. The historical VDM scaffold
does not carry a continuing product obligation.

## M4: Design Firmware And Product Surfaces

Retain lawful external firmware composition and Console/debugger interaction.

## M5: Fixed Standard Machine And Shared Core

Freeze an identified 386DX Standard board, firmware, display/storage set and
the PC110 evidence inventory. Converge build selection, construction and state
ownership to one profile per EXE; preserve all CPU families as an exception.
Retire other machine personalities through a coverage/dependency disposition.

Qualify the selected CPU, controllers and wiring through original function/
timing ledgers, code gaps and reference cross-checks. Exact manual values or
formulas are L3; range choices, reference/proportional models are L2; order-only
fallbacks are L1 and need explicit handling. Boot success is not a timing grade.

A bounded differential bridge and specification-driven tests support retained
CPUs and selected-board contracts. DOS/protected-mode and Windows 3.1
checkpoints follow hardware prerequisites; compatibility does not replace
hardware proof.

## M6: PC110 Hardware And CPU Qualification

Freeze the PC110 revision and lawful assets. Qualify its 486 variant and each
chipset/display/storage/input/power component through source, function/timing,
gap and integration ledgers. Reuse matching standard chip mechanisms; do not
infer complete PC110 support from AT registers or emulator placeholders.

## M7: PC110 Product Closure

Deliver the second executable through the same App/Common runtime, asset route
and dual host-architecture builds. Prove firmware, storage, display/input,
lifecycle and selected guest checkpoints; state excluded capabilities explicitly.

## M8 And Later: Evidence-Led Compatibility

Broaden either machine after hardware/corpus prerequisites. The former mantle,
owned-DOS and NXVDM milestones are withdrawn. New web, Windows 95 or unrelated
machine products require a separate owner decision.
