## Common Completion Contract

Each admitted implementation task consumes its predecessor's accepted commit and
records an explicit frozen coverage ledger before implementing a whole-domain
claim. Candidate proof batches below are minimum scope, not speculative S units.
Every source/test file in the imported inventory receives a disposition; changes
to that universe need an evidence-backed revision. No silent test deletion.

Each task runs the complete applicable shared unit suite on Windows x64 and x86,
its focused behavior/failure cases, manifest/dependency/static checks, and the
documentation gate. Register runtime cases in CTest with assertions enabled;
zero executed cases or an unsupported host is not a successful gate. Separate
native Console/Window checks from fake-provider tests and report both honestly.
External guest-ROM integration is not applicable to this shared-only milestone.
There is no placeholder NES executable or product artifact version.

Build selection: CMake >= 3.23, C11 required, extensions off, Release on both
architectures; local compiler paths supplied by environment/toolchain configuration,
never committed. Initial observed tools: CMake 4.3.3, MinGW GCC x64 16.1.0 and
i686 GCC 16.2.0. Revalidate tools at implementation admission and record exact
versions. Use -Wall -Wextra -Wpedantic -Werror for owned shared source/tests;
any unavoidable imported/platform diagnostic needs narrow justified treatment.
Preserve assertion checks with -UNDEBUG in tests. Do not claim C11 compatibility
from today's C17 build declarations: the import/build candidate must prove it.

The first task supplies portable configure/build/test presets named shared-x64
and shared-x86 and Lib/Common independent entry points accepting explicit roots.
Acceptance commands are cmake --preset shared-x64, cmake --build --preset
shared-x64 and ctest --preset shared-x64, repeated for shared-x86; these commands
are planned interfaces, not commands available in the current source-free tree.
Add complete-suite and static-check aggregation without hiding target dependencies.
CTest cases have finite timeouts (default 30 seconds); live host cases explicitly
declare their timeouts and process/resource cleanup. A timeout is failure, not
proof of bounded production responsiveness. Deterministic barrier/event tests
must prove ordering and cancellation; avoid correctness claims based on sleeps.

## Package And Handoff Boundaries

Queue defines execution order. The packages are import/build, neutral debug/driver,
executor lifecycle, input/presentation handoff, and transfer qualification.
Each depends on the preceding accepted package. They may contain multiple dynamic
S units, but have no reserved T/S numbers. Acceptance of this planning delivery
does not admit any implementation candidate automatically.

Preserve generic optional media/state-stream/heartbeat support if neutral; an
absent provider returns explicit unsupported. This is shared transport retention,
not admission of MyNes save states, disk support or host pacing. Keep existing
Linux source where licensed; M1 Windows qualification does not certify Linux.
Do not delete a supported source path merely because it is outside the host matrix.

M2 owns real NES load/debug/CPU behavior; M3 owns Core graphics-to-text conversion,
product key defaults and end-to-end dual gameplay; M4 owns actual guest pacing/audio; M5 owns
admitted product persistence/release. No tasks for those milestones are created.
M1 verifies existing frame-kind routing, mode transitions and input reset with
fake producers. Core publishes converted text in M3 when Console gameplay is
selected; Common does not need a new representation-selection protocol. Console
text-only acceptance is verified against the unchanged selected Lib baseline.
M1 also retains x86-debug/x86-xasm32 as separate optional components for receiving
App composition, with their own source/test disposition outside the neutral roots.
Common transports bounded debug content without defining product payload fields.
Generic byte storage and typed media/state transport remain; hardware-specific
semantics move to receiving adapters. Neither x86 assembly nor NES conversion
becomes a Lib feature. Actual sibling integration is separately admitted work.
