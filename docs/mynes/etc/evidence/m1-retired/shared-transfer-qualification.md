# Neutral Corpus Transfer Qualification

## Goal And Dependency

Consume all preceding M1 packages and the [M1 context](first-emulator-increment-planning.md).
Qualify one finite shared version for unchanged source/test adoption through external
product adapters. This task is proof/tooling and bounded in-scope repair, not actual
SoftPC/NXVM integration or automatic M1/M2 admission.

## Frozen Qualification Universe

Account for every imported unit and every resulting shared unit, all public driver
and transport capabilities, retained optional hooks, build entries, dependency edges,
and predecessor lifecycle/input/routing cases. Freeze the ledger at admission from
the accepted inventories; classify source unchanged/modified/removed with source and
destination hashes and tests retained/replaced/removed with semantic justification.
Every eligible obligation must pass; blocked obligations prevent M1 closure.

Produce one four-root manifest and neutral release identity. Export identical bytes
to two temporary owned consumer layouts whose root paths are supplied explicitly,
without editing shared files; build/run the suites on x86/x64. Re-hash before and
after. Inject two different fake
machine/debug consumers with different opaque payload layouts and published frame
kinds. Prove guest semantics stay outside the corpus while Common retains its
shared mode-switching mechanism. Verify Lib source/test/manifest hashes against
the selected upstream baseline, not just against the temporary export copies.
Qualify extracted x86-debug/x86-xasm32 separately as optional receiver components;
they are excluded from neutral-root manifests and Common's default dependency
graph. Negative dependency probes must
reject product includes, native APIs in Common and product-name build branches.

Record receiving-adapter migration obligations: driver creation/lifetime, debug
operation codecs and x86 command/xasm ownership, lifecycle completion/generation,
input-reset mapping and Core/receiver frame production consumed by existing Common
mode switching. Describe the receiving App's explicit assembly of x86-debug and
x86-xasm32 with the machine debug adapter; record moved source/tests and protocol
ownership, preserving x86 behavior outside Common's default build.
Every receiving machine adapter owns any graphics-to-text conversion it requires;
shared kvm-console accepts only prepared text frames. Exported fixtures prove
text delivery and rejection of graphics without a converter in Lib/Common.
Inspect the pinned SoftPC and NXVM consumer surfaces to ground that table; do not edit or build siblings.
Identical source/hash and fake consumers prove transferability within this boundary,
not compatibility of unchanged old adapters or completed real-product reintegration.

## Acceptance And Stop Conditions

Run the full common completion contract and independent exported-layout gates;
reconcile every Roadmap M1 exit with direct evidence and retained limits. No source,
test, notice or contract can disappear between manifests without disposition.
No generic capability failure may be deferred to M2 merely to close M1. Return a
discovered Common defect through bounded corrective admission. A Lib defect or
unfinished upstream CP437/text-contract dependency blocks qualification pending
upstream resolution and reviewed import; no receiving-product Lib fork is allowed.
Deliver M1 closure evidence for coordinator review; Current records closure only
after those gates pass. M2 remains unadmitted and without a task decomposition.
