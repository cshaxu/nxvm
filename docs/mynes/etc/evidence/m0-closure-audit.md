## Findings And Repairs

1. Execution/checker demanded emulator presets/artifacts after any numeric
   implementation, contradicting approved shared-only M1. Added a constrained
   shared-foundation baseline for admitted M1 and shared x86/x64 build/test evidence;
   product mode remains mandatory for App/Core. Current remains documentation-only.
2. Every implementation T required external ROM tests, including fake-machine
   corpus work. Clarified applicable suite admission and explicit non-applicability
   for shared-only work; previously admitted suites cannot be waived.
3. Checker scanned only legacy test/, missing planned src/test documentation.
   Added src/test coverage and a negative broken-link probe; retain legacy scanning
   to detect leftover documents rather than create a second approved source map.
4. AGENTS could imply that import approval permits sibling mutation. Clarified
   source-read/destination-write authorization without changing source policy.
5. UI/Coding still referred all capability detail to the sole queued M1 candidate.
   Corrected those references to the relevant milestone's admission planning.

Similar-issue sweep covered all current authorities and checker branches.
Historical S1-S5 evidence remains unchanged. No new product capability, T task
or milestone admission is introduced by these governance repairs.
