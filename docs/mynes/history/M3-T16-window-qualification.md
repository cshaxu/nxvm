# M3 T16: Window-First Presentation Qualification

T16 consumes the first implementation candidate. It proves the real Win32 Window
route from process configuration through Common UI and production Core pixels,
then records failure/teardown evidence. Console gameplay is excluded.

## S1 Native Window Receiver

The product now has a Windows-only integration receiver,
`mynes.integration.native-window-smoke`.  It builds an original NROM-128 fixture,
uses the same App command provider and Common Session/UI wiring as composition,
then runs the production Core driver with Window output.  The receiver waits for
the real `LibKvmWindow`, reads its client DC, and requires a non-black initial
pixel.  It posts the mapped K=A key through the native Window procedure and
requires an observed pixel change from the actual client DC.

The same receiver verifies F12 pause, F5 pause/resume, the corresponding native
Window title changes, and `WM_CLOSE` retirement followed by a paused machine and
safe session teardown.  The Window receiver passed on both x64 and x86.
`test/app/config_smoke.c`
now also proves explicit and default `video = window` select Core pixel output.
No Lib or Common source changed.  The self-authored fixture is generated by the
test and remains an ignored build-time artifact.

## Acceptance And Transfer

T16 accepts the Window-first outcome. Targeted x64/x86 configuration and native
Window receivers pass. The x64 full suite reached 102/102 passing tests. The x86
full suite reached 101/102: the unchanged imported
`library.kvm_window_capture_contract` reproducibly terminates with a SegFault
when run alone. `src/lib` and `test/lib` are unchanged in this delivery, so the
defect is not repaired in a product Window task. It transfers as R12 to the next
release-qualification task, which must establish the source and a reviewed
resolution without violating the adopted-root rule.

Console text-frame gameplay remains queued and is not implied by this Window
acceptance.
