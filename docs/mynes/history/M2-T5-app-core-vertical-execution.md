## S1 Result And S2 Admission

S1 created the real `mynes` executable and its flat App/Core component targets.
The product composes one Core driver with the existing Common machine, session
and UI; it accepts `--rom`, starts the cooked monitor, and supplies the frozen
command vocabulary. Core now owns strict NROM parsing, copied cartridge data,
the 2 KiB CPU-RAM mirror, NROM PRG mapping, explicit device/open-bus policy and
the single resumable 12-form CPU engine. The owned source fixture proves reset
from $FFFC, A=$2A to $0200, X=10 through BNE, and the $800D JMP checkpoint.

The S1 x64 Debug build used MinGW GCC 16.1.0. `mynes`, Core, App and lifecycle
test targets compile with strict C11; product tests pass for parser, command
provider, machine checkpoint and Common lifecycle/media replacement. The
available host has no `i686-w64-mingw32-gcc` or other x86 compiler, so x86
artifact evidence is not claimed. The ignored build tree contains no release
artifact claim.

S1 does not close T5: the frozen acceptance matrix still requires independent
per-opcode timing/flag cases, command-flow coverage through the actual monitor,
and a deterministic paused observation proof. S2 is admitted with only those
completion obligations. It may repair MyNes-owned App/Core/test/build code, but
must not modify the adopted Lib/Common corpus. T5 closes only after the complete
vertical package is checked, its product artifact status is recorded, and the

## S2 Progress

S2 added an independent profile for every frozen opcode's base timing and
observable flag/data effect, including both BNE outcomes. The real Common/Core
lifecycle test now acquires a paused lease and executes OBSERVE after the
executor has reached its service point. It proves zero retirement after reset,

The actual x64 Release executable was also exercised through an interactive

reported no cartridge and accepted `quit` with exit code zero. With the owned

paused.`, then `status` reported an inserted cartridge and `quit` exited cleanly.
