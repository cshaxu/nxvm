# Queue

This is the ordered, unnumbered candidate queue. It does not activate work,
reserve a numeric task identifier, or define a technical baseline. The first
approved candidate enters [STATUS.md](STATUS.md) and receives the next linear
numeric identifier under [rules/EXECUTION.md](rules/EXECUTION.md).

1. **Pre-decode transition registry, conditional.** Admit only for a concrete
   first-party consumer. It matches a decoded form before execution and exposes
   checked copied state with finite resume/fault/stop/switch results; no guest
   service ABI or second decoder.
2. **Ordinary-RAM transaction.** Add a stopped/paused copied-value multi-span
   transaction only after its consumer and preflight/atomicity contract are
   explicit.
3. **Transition-local combined commit, conditional.** Combine a checked staged
   RAM write with an allowed decoded-transition patch only when an admitted
   consumer needs both at one boundary.
4. **Core second-consumer readiness.** Prove the first policy-free consumer
   with a core-only fixture and retained NXVM regressions; do not create mantle.
5. **80386 enhanced-mode checkpoint.** Select the next failing owned corpus
   requirement, beginning with the Setup `MOV CR0,EAX` control transition.
6. **Next CPU/FPU readiness increment.** Choose only from a failing prepared-
   state or system corpus; do not claim broad 386/FPU completion.
7. **Windows 3.x readiness map.** Record the bounded checkpoint and every
   remaining prerequisite; no Windows 95 claim.
8. **M5 closure audit.** Reconcile current source, product UX, contracts,
   CMake, evidence, and open debt before any M5-close decision.
