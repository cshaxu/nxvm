# Roadmap

## M0: Governance, Research And Design

Establish independent authorities/MTSP/Queue, exact roots, lawful-source policy,
hardware/reuse inventory, single-owner architecture and bounded M1 proposals.
Source/set uncertainties must be explicit receiving gates, not invented facts.
M0 exit is a reviewable complete plan and owner acceptance. It creates no
runnable scaffold, ROM import, shared runtime patch or gameplay qualification.

## M1: Implementation And Playable Qualification

Requires explicit M0 acceptance and M1 admission. The Queue contains ordered
unnumbered tasks: source/set freeze; V30; board/COP; video; sound; host/product
integration; full gameplay qualification. Each numeric T is allocated only on
admission and splits into bounded S batches from actual evidence.

Exit: the fixed original board/set passes its entire finite convergence ledger,
including real game startup, controls, video, sound, stage/end/restart and host
lifecycle/failure cleanup. Both host widths pass complete owned/receiving units,
required integrations and release identity/PE/hash checks; the latest dual
EXEs are committed/pushed and owner gameplay acceptance is recorded.

Compile success, synthetic CPU tests or one title screen cannot close M1.
Additional games, later boards and universal arcade abstractions require new
owner admission, not a speculative M2 roadmap or accidental scope expansion.
