# Goal

Implement MyRaidenII, a C11 emulator for one explicitly selected original
V30-based RAIDEN II board/ROM revision. Required product outcome is playable
boot/attract/coin/start/gameplay/stage completion/game-over/restart with working
video, input and sound, delivered on Windows x64 and x86.

M0 establishes governance, architecture, sources, gaps and M1 task boundaries.
M1 implements and qualifies that outcome. M0 is not an emulation or executable
release; completion cannot be inferred from a title screen or a timeout.

The game is an arcade board, not an IBM PC. Do not inherit PC BIOS, chipset,
memory mapping, storage media or hotkeys merely because the main CPU is x86-like.
V33-based later Raiden II/DX, Raiden DX, other Seibu games, Metal Slug 2 and
Neo Geo are outside the initial product. A universal arcade framework is not
an objective.

One fixed board/set is qualified first. M1's first task freezes its identity
against lawful owner assets and sources. No game ROM is downloaded, committed
or embedded in product EXEs. Existing PC firmware publication exceptions do not
extend to game content. Runtime input comes from the external owner archive.

Accuracy is stated per mechanism: original-source facts and exact formulas
are distinguished from reference-derived L2 models and unresolved evidence.
Playable does not mean cycle-exact, all variants or all physical effects.

Missing physical-hardware evidence does not by itself block an owner-valid
implementation.  Use directly applicable original facts as L3; use observable
external-emulator behavior as L2 without copying its source or tables; when
neither establishes a complete rule, an explicitly bounded L1 model is
permitted.  An L1 receiver still states its inputs, outputs, reset and failure
behavior and has a local synthetic oracle.  Its grade is not upgraded merely
because it allows the selected set to proceed.
