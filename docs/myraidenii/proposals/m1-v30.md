# NEC V30 Qualification

Admitted as MyRaidenII M1 T2 on 2026-10-17 after T1 freeze acceptance.
Current owns the active S packet; the complete task domain and dispositions
belong to the [V30 convergence ledger](../etc/t2-v30-ledger.md).

## Objective And Prerequisites

After board/source freeze, implement the selected V30 execution contract at
the approved CPU owner. X86 Core had no V30 profile at admission. This proposal
does not itself authorize changes to Shared source or public interfaces.
On 2026-10-17 the owner separately approved V30 profile, NEC instruction-space
and necessary V30 timing-origin enum additions/integration, preserving existing
values, signatures and opaque/public layouts. No Lib or Emulator change is
approved. The exact admitted CPU S must record every affected consumer and
verification; this is not unrestricted permission to expand the public API.

## Work And Boundary

Audit instruction/flag/interrupt/addressing differences against primary NEC
documentation and selected game use. Reuse proven Intel mechanisms only where
semantics match; do not identify a V30 as 8086/386 or copy a second interpreter
into the App. Fix interrupt acknowledgement, bus effects, bounded execution
and timing source grades as complete batches rather than one opcode per S.

## Exit And Stops

Run ROM-free vectors for the finite V30 ledger, actual board instruction-path
checkpoints and both host-width regressions for all affected existing CPU
profiles. Label incomplete timing honestly; no silicon-exact claim from MAME.
Public-boundary or source/license changes require review before implementation.
CPU completion alone is not game compatibility.

## Bounded Batches And Completion Predicate

S1 freezes native-primary, NEC-extension and 8080 domains and all cross-cutting
state/bus/time contexts, using the current sources and original NEC manual.
Subsequent admissions consume complete mechanisms: family/reset/form admission;
native execution including NEC forms; emulation/entry/repeat; source-graded
timing/neutral Machine; then complete qualification and existing consumers.
The exact next S scope follows the evidence, not one opcode per subtask.

No V30 CPU qualification is complete while a documented mode, form, entry,
bus or timing member remains unimplemented/unqualified. Undefined/unspecified
behavior requires a source-backed model disposition, not fabricated silicon
accuracy. Original board-path checkpoints remain required, with diagnostic
budgets used only for containment. Preserve existing Intel behavior and prove
all affected x64/x86 units and eight current PC artifacts before Shared batch
closure. MyNES has no X86 Core dependency and is not rebuilt for CPU-only work.
