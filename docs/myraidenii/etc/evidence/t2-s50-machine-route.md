## Attempts And Corrections

Ninja rejected the unknown target before compiling. Reading the actual common
registration corrected it to x86-core-test-machine-machine_v30_execution.
The first mode run completed all eleven instructions but failed the test's
incorrect late-Intel reset-vector assertion. Existing CPU reset source and
the retained V30 reset contract useFFFF:0000, physicalFFFF0, notF000:FFF0.
Correcting that independently selected expected value changes no production.

The first refusal run reached the intended fault and accepted-time checks,
then incorrectly attempted a pure observation through operational debug_read_memory.
The public memory contract explicitly distinguishes read from inspect. The test
now uses memory_inspect for the observational predicate, retaining both APIs and
their existing behavior. This does not silently claim every debugger read is
side-effect-free. No production defect or new rollback path was inferred from
either mistaken test assertion.

Final source/test inputs were frozen after adding matching successful device
cases and mode-specific attached deadlines. Early incremental builds and probes
are development evidence, not full qualification of those final inputs.
