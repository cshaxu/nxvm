## Sole Repair And State Boundary

Existing ExecInt correctly selects NMI/INT first, but the step generated by
the completed instruction remains queued and is delivered again immediately.
The existing successful real-entry owner now clears that superseded step and
its cause only after all frame/vector/CS work succeeds, for NEC entries which
disable interrupts. No new pending queue, arbitration object, public API,
enum, stored state, executor or clock exists. Intel entry and non-disabling
BRKEM/CALLN retain their original paths.

Failure before successful external entry preserves the old pending step;
CPU execution stops on provider failure and accepted writes are not replayed.
The winning step's own existing delivery consumes its request before trying
the entry; a provider failure still stops CPU execution rather than retrying
that prefix. These are distinct responsibilities, not a reason to add a new
retry mechanism or silently change Intel policy.
